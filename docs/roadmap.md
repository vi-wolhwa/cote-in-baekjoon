기한이 정해져 있지 않아 날짜 대신 **완료 조건**으로 관리한다. 각 마일스톤은 GitHub Milestone으로 만들고, 기능 단위 이슈로 쪼갠다.

| 마일스톤 | 목표 | 완료 조건 |
|---|---|---|
| **M0 기반** | 개발을 시작할 수 있는 상태 | 아래 M0 항목 완료 |
| **M1 MVP** | JavaScript로 한 문제를 처음부터 끝까지 푼다 | PRD 6.1의 F1~F10 동작, 제품 책임자 사용 테스트 통과 |
| **M2 언어 확장 1** | Python, C++ 지원 | 두 언어로 실행·제출 가능, 첫 실행 속도 기준 충족 |
| **M3 공개** | Java 지원, 저장소 공개와 피드백 창구 | Java 실행·제출, 저장소 공개, 확장 팝업·문제 신고·이슈 템플릿, 유지보수·업데이트 체계 문서 |

| **M6 언어 확장 2** | 백준의 기타 언어 (ADR-0007) | C99·C11·C++14·C++20·Java 8·TypeScript 실행·제출, Kotlin·Rust·Go·Swift·C#·Ruby 제출(코드 실행은 이유와 함께 꺼짐). 그 밖의 언어와 제출만 되는 언어의 실행은 사용자 피드백으로 결정 |
| **M7 제출 기록** | 문제별 제출 기록 탭 | 풀이 화면에서 지난 제출과 결과 확인 |
| **웹스토어 출시** | 크롬 웹스토어 첫 게시 | 위 마일스톤 모두 완료, 유지보수·업데이트 체계 확보, 제품 책임자 승인(#206) |
| **운영** | 피드백과 유지보수 | GitHub 이슈 기반 (M3에서 체계 마련) |

## M0 기반 작업

1. 저장소 생성 (Private), 기본 문서 (PRD, 로드맵)
2. 기술 검증 스파이크 R1~R3 (PRD 10장)
3. 기술 스택 결정과 ADR 작성
4. 개발 규칙: 브랜치 전략, 커밋·PR 규칙, 코드 스타일, 이슈·PR 템플릿, 라벨
5. CI: PR마다 린트, 타입 검사, 테스트, 빌드
6. 확장 프로젝트 뼈대: MV3 manifest, 빌드, 개발용 로드 방법
7. 풀이 화면 디자인 시안 → 제품 책임자 확인
