## 1. 한 줄 요약

백준(acmicpc.net) 문제를 기업 코딩테스트와 같은 풀이 화면에서 풀 수 있게 해 주는 크롬 확장 프로그램.

## 2. 배경과 문제

- 기업 코딩테스트는 대부분 프로그래머스 같은 웹 IDE 환경에서 치른다. 문제 설명, 코드 에디터, 실행 결과가 한 화면에 있고, 예제로 먼저 실행해 본 뒤 제출한다.
- 연습은 문제 수가 압도적으로 많은 백준에서 하는 사람이 많다. 그런데 백준은 문제 페이지와 제출 페이지가 나뉘어 있고, 제출 전에 예제를 돌려 볼 기능이 없다. 보통 로컬 IDE에서 짜서 붙여 넣는다.
- 그래서 연습 환경과 실제 시험 환경이 다르다. 시험장에서 낯선 에디터, 실행 흐름, 시간 압박에 적응하느라 실력을 다 못 낸다.

## 3. 목표와 비목표

### 목표
1. 백준 문제를 기업 코딩테스트 풀이 화면과 같은 **배치와 조작감**으로 풀 수 있다.
2. 제출 전에 예제와 직접 추가한 테스트 케이스로 **브라우저 안에서 코드를 실행**해 볼 수 있다.
3. 그 화면에서 바로 **백준에 제출하고 채점 결과를 확인**할 수 있다.
4. 이후 문제 세트를 만들어 **실제 시험처럼 시간 제한을 두고** 풀 수 있다 (M4).

### 비목표
- 화면 공유, 웹캠 등 실제 시험의 감독 기능
- 프로그래머스의 이름, 로고, 고유 색상, 고유 디자인 자산 사용 (8장 참고)
- 자체 채점 서버 운영. 최종 채점은 항상 백준이 한다.
- 사용자 데이터 수집. 모든 데이터는 사용자의 브라우저에만 저장한다.

## 4. 사용자

- **주 사용자**: 코딩테스트를 준비하면서 백준으로 연습하는 사람 (백준 사용자 전반)
- **전제**: 백준 계정이 있고 확장을 쓰는 브라우저에서 백준에 로그인되어 있다.
- **지원 브라우저**: Chrome, Microsoft Edge, 네이버 웨일 (모두 Chromium 기반이라 같은 패키지로 동작)
- **화면 언어**: 한국어

## 5. 핵심 사용자 흐름 (MVP)

1. 백준 문제 페이지(`/problem/{번호}`)를 연다.
2. 문제 제목 옆에 확장이 넣은 **"코테 화면으로 풀기"** 버튼을 누른다. 버튼은 백준 디자인에 어울리되 눈에 띄게 강조한다.
3. 풀이 화면이 열린다. 왼쪽에 문제, 오른쪽 위에 에디터, 오른쪽 아래에 실행 결과가 있다.
4. 언어를 고르고 코드를 작성한다. 코드는 문제·언어별로 자동 저장된다.
5. **코드 실행**: 백준 예제와 직접 추가한 테스트 케이스로 브라우저 안에서 실행한다. 케이스마다 입력값, 기댓값, 실행 결과, 통과 여부를 본다.
6. **제출하기**: 백준 공식 제출 페이지가 열리고 언어와 코드가 자동으로 채워진다. 사용자가 백준의 제출 버튼을 **직접** 누른다 (8.1 참고).
7. 채점이 끝나면 결과(맞았습니다, 틀렸습니다, 시간 초과 등과 메모리·시간)를 풀이 화면에서도 확인한다.

## 6. 기능 요구사항

### 6.1 MVP (M1)

| ID | 기능 | 설명 |
|---|---|---|
| F1 | 진입 버튼 | 백준 문제 제목 옆에 풀이 화면을 여는 버튼을 넣는다 |
| F2 | 문제 패널 | 백준 문제 본문(설명, 입력, 출력, 예제, 힌트, 시간·메모리 제한)을 표시한다. 이미지와 수식도 표시한다 |
| F3 | 코드 에디터 | 프로그래머스 풀이 화면의 에디터와 같은 기능·테마·단축키를 제공한다 (8장) |
| F4 | 언어 선택 | MVP는 JavaScript(Node.js 표준 입출력)만 지원한다 |
| F5 | 코드 실행 | 예제를 브라우저 안에서 실행해 케이스별 결과를 프로그래머스와 같은 출력 형식으로 보여 준다. 무한 루프는 시간 제한으로 끊는다 |
| F6 | 테스트 케이스 추가 | 입력과 기댓값을 직접 추가·삭제한다. 문제별로 저장한다 |
| F7 | 초기화 | 코드를 기본 템플릿으로 되돌린다. 되돌리기 전에 확인한다 |
| F8 | 제출 | 백준 제출 창을 열어 언어·코드를 자동으로 채운다. 제출 버튼은 사용자가 누르거나, 사용자가 켠 경우 자동으로 누른다(8.1). 채점이 끝나면 창을 닫고 결과를 풀이 화면에 보여 준다 |
| F9 | 자동 저장 | 코드와 테스트 케이스를 문제·언어별로 브라우저에 저장한다 |
| F10 | 패널 크기 조절 | 문제·에디터·결과 패널 경계를 드래그해 크기를 바꾼다 |

입출력 방식은 백준과 같은 **표준 입출력**이다. 프로그래머스식 `solution` 함수는 M5에서 추가한다.

### 6.2 이후 버전

| 마일스톤 | 기능 |
|---|---|
| M2 | Python, C++ 실행·제출 |
| M3 | Java 실행·제출, 웹스토어 첫 공개 게시 |
| M4 | 문제 세트와 모의 시험 모드. solved.ac 티어, 알고리즘 태그, 문제 수로 세트를 만들고 시간 제한 안에서 여러 문제를 푼다 |
| M5 | `solution` 함수 템플릿. 문제의 입력 형식과 예제에서 파라미터를 추론해 제공하고, 제출할 때 입출력 코드를 자동으로 붙인다 |
| M6 | 백준이 지원하는 다른 언어 |
| 운영 | GitHub 이슈로 사용자 피드백 수집, 유지보수 체계 (배포 후 결정) |

## 7. 비기능 요구사항

- **권한 최소화**: 접근 사이트는 `acmicpc.net`(M4부터 `solved.ac` 추가)만. 필요한 권한만 요청한다.
- **원격 코드 금지**: 웹스토어 정책상 실행 엔진(언어 런타임)은 모두 확장 패키지 안에 넣는다. CDN에서 내려받아 실행하지 않는다.
- **격리 실행**: 사용자 코드는 확장의 다른 부분과 분리된 샌드박스에서 실행한다.
- **백준 부담 최소화**: 백준 요청은 사용자의 직접 행동(화면 열기, 제출)으로만 보낸다. 백그라운드 크롤링은 하지 않는다.
- **개인정보**: 수집하지 않는다. 저장은 브라우저 로컬(`chrome.storage`)만 쓴다. 웹스토어 게시 때 이를 밝힌 개인정보처리방침을 낸다.
- **성능**: 풀이 화면은 버튼을 누르고 1초 안에 열린다. JavaScript 실행 결과는 1초 안에 보인다 (무거운 런타임은 M2 이후 별도 기준).

## 8. 브랜드와 디자인 원칙

- **이름**: 코딩테스트 in 백준 (영문 `cote-in-baekjoon`)
  - '백준'은 이 확장이 동작하는 사이트를 밝히는 용도라 다른 확장들처럼 써도 된다고 판단했다.
  - '프로그래머스'는 이 확장이 그 서비스와 함께 동작하지 않는데도 이름에 쓰면 제휴나 보증처럼 보인다. 그래서 웹스토어 정책(타사 사칭·상표) 위험이 있어 빼기로 결정했다.
- **풀이 화면**: 프로그래머스 풀이 화면과 **같게** 만든다.
  - 같게 만드는 것: 배치, 에디터 기능, 테마 색, 글꼴, 버튼 구성과 문구, 실행 결과 출력 형식
  - 제외하는 것: 프로그래머스 이름, 로고, 아이콘 같은 상표성 요소
  - 그들의 이미지·스타일시트·스크립트 파일은 복사하지 않는다. 측정한 값으로 직접 다시 만든다.
- **백준에 넣는 UI**: 백준 디자인 시스템과 어울리게 만들되 사용자가 기능을 알아챌 수 있게 시각적으로 강조한다.

### 8.1 제출 원칙

[백준 이용 규칙](https://help.acmicpc.net/rule)은 공식 `/submit` 페이지에서 사용자가 직접 제출 버튼을 누르지 않는 모든 제출 수단을 자동 제출 도구로 본다. 적발되면 제출한 소스가 모두 삭제되고 제출이 금지된다.

**기본 동작 (직접 제출)**
- 확장은 공식 제출 페이지를 열고 언어와 코드를 채운다.
- 제출 버튼은 사용자가 누른다.

**자동 제출 (사용자 선택, 2026-11-24 제품 책임자 결정, #41)**
- 사용자가 위험 안내를 읽고 켠 경우에만, 채운 뒤 백준의 제출 버튼을 대신 누른다.
- 누르기 직전 1.2초 동안 취소할 수 있다.
- 첫 제출 때 안내 대화상자로 묻고, 하단 '자동 제출' 설정으로 언제든 바꿀 수 있다.
- 다음 경우에는 자동 제출하지 않고 직접 제출로 돌아간다.
  - 보안 확인(CAPTCHA 등)이 있을 때. 보안 확인은 우회하지 않는다.
  - 방화벽에 막힐 문자열이 있을 때
  - 채우기가 불완전할 때
- 제출 요청을 직접 만들어 보내지는 않는다. 페이지의 버튼을 누르는 것뿐이다.
- 이 기능은 백준 규칙에 어긋나며 위험은 사용자 계정에 있다. 웹스토어 공개 전에 운영사 문의 결과를 반영한다.

**공통**
- 문제는 사용자가 보고 있는 페이지에서 읽는다.
- 채점 결과도 페이지에서 읽는다. 실시간 갱신이 오지 않을 때만 방금 낸 제출 1건을 `/status/ajax`로 확인한다(ADR-0002).

## 10. 위험과 검증 계획

M1 개발 전에 기술 검증(스파이크)으로 확인한다.

| ID | 위험 | 확인할 내용 |
|---|---|---|
| R1 | 백준 제출 | **확인 완료**: 직접 제출은 백준 규칙 위반이다. 자동 입력 + 사용자 클릭으로 결정 (ADR-0002). 자동 입력 허용 여부는 운영사 문의 필요 |
| R2 | 문제 본문 | **확인 완료**: 열려 있는 문제 페이지의 DOM에서 읽고 같은 MathJax 설정으로 표시 (ADR-0001) |
| R3 | 코드 실행 | **방식 결정**: 샌드박스 페이지 + 워커 (ADR-0004). 뼈대 작업에서 실제 동작 검증 |
| R4 | 무거운 언어 | Python·C++·Java 런타임을 패키지에 넣었을 때 크기와 첫 실행 속도가 쓸 만한지 (M2 전에 확인) |
| R5 | 웹스토어 비용 | 개발자 계정 등록비(1회 $5)가 '무료만' 조건과 충돌한다. M3 전에 제품 책임자와 결정한다 |
| R6 | 백준 화면 변경 | 백준이 HTML 구조를 바꾸면 기능이 깨질 수 있다. 파싱 코드를 한곳에 모으고 테스트로 감시한다 |
