# 풀이 화면 디자인 명세

PRD 8장 결정에 따라 풀이 화면을 기업 코딩테스트 풀이 화면(프로그래머스 연습 화면)과 같게 만든다.

- 이 문서의 값은 2026-11-23에 1440×900 화면에서 로그인 없이 실제 화면의 계산된 스타일을 측정한 것이다.
- 그쪽의 이미지·스타일시트·스크립트 파일은 쓰지 않는다. 이 값으로 직접 구현한다.
- 이름·로고·아이콘은 쓰지 않는다.
- 측정하지 못한 항목은 **[미확인]** 으로 표시했다.

## 4. 에디터 동작

- 줄 번호, 자동 줄바꿈, 탭 크기 4, 들여쓰기 4칸(공백), 현재 줄 강조(텍스트를 선택하는 동안에는 끈다. 현재 줄 배경이 선택 영역을 가리지 않게), 괄호 짝 표시, 괄호 자동 닫기
- 키맵: 기본 `sublime`, `vim`, `emacs` 중 선택. 선택은 저장해서 유지한다.
  - sublime: 선택 영역에서 Tab은 들여쓰기, Shift-Tab은 내어쓰기
- 파일 탭 이름: `solution.<확장자>` (Java 표준 입출력은 `Main.java`, solution 함수 모드는 `Solution.java`, 7.2)
- 언어 선택: 목록에서 고른다. 이 제품은 백준 언어 ID에 맞춘다 (PRD 6장 순서).
  - 목록은 `<optgroup>` 두 묶음이다: **브라우저에서 실행**(C99, C11, C++14, C++17, C++20, Python 3, PyPy3, Java 8, Java 11, JavaScript, TypeScript)과 **제출만**(Kotlin (JVM), Rust 2021, Go, Swift, C#, Ruby). 선택 상자 모양은 그대로다 (ADR-0007).
  - 제출만 되는 언어: '코드 실행' 버튼이 꺼지고(마우스를 올리면 이유), 실행 결과 탭 위에 "이 언어는 브라우저에서 실행할 수 없어요. 제출하면 백준이 채점해요"를 보인다. 제출하기는 그대로다.
  - 모든 언어에 solution 함수 연결 코드가 있다(ADR-0008). 연결 코드가 없는 언어가 생기면 스위치가 꺼지고 "{언어}에서는 solution 함수를 쓸 수 없어 표준 입출력으로 풀어요"를 보인다.

## 5. 버튼과 대화상자

**하단 바 순서**
- 왼쪽: 질문하기(백준 질문 게시판 링크, 테스트 케이스 추가하기와 같은 어두운 버튼), 테스트 케이스 추가하기
- 오른쪽: 초기화, 코드 실행, 제출하기(주 버튼)
- 질문하기·다른 사람의 풀이는 백준의 질문 게시판·맞힌 사람 링크로 대신할지 M1에서 정한다.

**초기화 대화상자**
- 제목: 초기화 안내
- 본문: "지금까지 작성한 모든 코드가 삭제되고 문제를 처음 시작했을 때의 상태로 돌아갑니다. 초기화 하시겠습니까?"
- 버튼: 취소, 확인
- 확인 후 결과 창: "코드를 초기화하였습니다."

**테스트 케이스 추가**
- 제목: 테스트 케이스 추가
- 표준 입출력 문제는 Input / Output 열을 쓴다.
- 배치는 **[미확인]** 이다.

**실행 중**: 중지 버튼이 나타나고, 중지하면 "실행 중단"을 표시한다.

## 6. 실행 결과 출력 형식

- 구분 기호는 "〉"(U+3009, 불투명도 32%)다.
- 라벨은 오른쪽 정렬된 10rem 폭 열에 `#44576C`로 쓴다.
- 빈 상태: "실행 결과가 여기에 표시됩니다."

```
테스트 1
     입력값 〉 1 2
     기댓값 〉 3
   실행 결과 〉 테스트를 통과하였습니다.
        출력 〉 (표준 출력이 있을 때만)
```

**통과·실패 문구**
- 통과는 파란색이다.
- 실패는 빨간색으로 "실행한 결괏값 X이(가) 기댓값 Y와(과) 다릅니다."를 표시한다.

**요약**
- "테스트 결과 (~˘▾˘)~" 제목 뒤에 "N개 중 M개 성공"을 쓴다. 모두 통과하면 파란색, 아니면 빨간색이다.
- 모두 통과하면 다음 안내를 덧붙인다: "샘플 테스트 케이스를 통과했다는 의미로, 작성한 코드가 문제의 정답은 아닐 수 있습니다."

**오류**
- 런타임 에러: 빨간 제목 "런타임 에러", 그 아래 표준 에러 내용
- 상태 문구: 실패, 시간 초과, 메모리 초과, 런타임 에러, 출력 크기 초과
- 시간 초과 설명: "실행 시간이 N초를 초과하여 실행이 중단되었습니다. 실행 시간이 더 짧은 다른 방법을 찾아보세요."

**채점 결과** (제출 후, 백준 결과를 이 형식으로 보여 준다)
- "채점을 시작합니다." 뒤에 결과 줄이 나온다. 예: `정확성 테스트 〉 맞았습니다!! (12ms, 11.2MB)`

## 7. 문제 영역

- 안쪽 여백 16px, 영역 안에서 세로로 스크롤한다. 맨 위에 '문제 설명' 라벨이 있다. 연습 풀이 화면에서는 라벨 대신 '문제 설명 | 제출 기록' 탭(7.3)을 둔다. 시험 화면은 라벨 그대로다.
- 섹션 사이에 `hr`(1px `#172334`, 위아래 24px)을 둔다.
- 표: 셀 `#202B3D`, 테두리 1px `#172334`, 안쪽 여백 4px 12px
- 코드 블록: 배경 `#202B3D`, 안쪽 여백 20px 24px, 반경 4px
- 백준 문제는 섹션 순서대로 표시한다: 문제, 입력, 출력, 제한, 예제 입력·출력, 힌트
- 한국어가 아닌 문제(ADR-0010)는 '문제 설명' 아래 번역 막대를 둔다(13px). 상태별로 다음을 보인다.
  - 번역됨: 칩 모양 토글 '번역 | 원문'(26px, 고른 쪽 강조)과 "영어에서 기계 번역했어요"(원문이면 "영어 원문")
  - 원문을 고른 상태로 연 문제: '한국어로 번역' 버튼과 "영어 문제예요."
  - 웹 번역이 안 되어 기기 안 번역 모델을 내려받아야 함: '한국어로 번역' 버튼과 "영어 문제예요. 처음에는 번역 모델을 내려받아요."
  - 번역 중: "번역하는 중…(모델 n%)"
  - 실패(웹·기기 안 모두): "번역하지 못해 원문으로 보여요."와 '다시 시도'
- solution 함수 모드에서는 예제 입력·출력 대신 **입출력 예** 표를 보인다: 매개변수마다 한 열과 `result` 열(머리글 굵게, `--cell-bg`), 예제의 케이스마다 한 행. 값은 리터럴로 쓴다(`3`, `[3, 1, 2]`, `"abc"`). 고정폭 14px, 긴 값은 줄바꿈, 표가 넓으면 가로 스크롤. 형식으로 읽을 수 없는 예제는 원래 블록으로 남긴다. 표준 입출력으로 바꾸면 예제 블록으로 돌아간다

## 7.1 제출 (백그라운드 탭)

ADR-0002(2026-11-24). '채점 결과' 탭:
- 제출 중: 16px 도는 원(테두리 2px, 위쪽만 `#0078FF`)과 굵은 "제출 중", 안내 한 줄, '직접 확인' 버튼(13px 600, 반경 4px, 어두운 버튼).
- 채점 중: 도는 원과 "채점 중 · 채점 중 (35%)", '직접 확인'.
- 백준이 "기다리는 중"(채점 대기열)을 10초 넘게 보이면 그 아래 안내 한 줄(`out-note`): "기다리는 시간은 백준 채점 서버 상황에 따라 달라져요." 채점이 시작되면 사라진다.
- 직접 확인이 필요해요: 경고색 굵은 제목, 이유 한 줄, 파란 '직접 확인'.
- 결과를 아직 못 받았어요: 경고색 굵은 제목, 설명, 파란 '결과 다시 확인'.
- 최종 결과: "채점을 시작합니다." 아래 결과 표(이전과 같다).
- 동작 줄이기 설정이면 원이 3초에 한 바퀴로 천천히 돈다.

## 7.2 solution 함수 (ADR-0006)

참고 화면은 측정하지 않았다. 풀이 화면의 토큰(칩, 선택 상자, 결과 버튼)을 그대로 쓴다.

**스위치** (제목 줄, 키맵 왼쪽)
- `solution 함수` 스위치(높이 24px, 칩과 같은 테두리·배경). 켜지면 칩 강조 배경과 파란 트랙.
- 기본 켬. 켜고 끈 선택은 언어처럼 저장하고(`ui:solution`) 모든 문제에 쓴다.
- 쓸 형식이 없으면 꺼진 채로 흐리게(`aria-disabled`) 보이고, 마우스를 올리면 이유를 보인다: "입출력 형식을 알 수 없어 표준 입출력으로 풀어요". 인터랙티브·함수 구현 문제는 "인터랙티브·함수 구현 문제는 표준 입출력으로만 풀 수 있어요".
- 형식이 없을 때(제외 문제 빼고) 옆에 점선 칩 '형식 만들기'. 누르면 입출력 형식 카드를 열어 정의한다.
- 바꾸면 지금 코드를 그 방식의 키에 저장하고 다른 방식의 코드(없으면 시작 코드)를 보인다. 실행 결과는 비운다.

**입출력 형식 카드** (파일 탭과 에디터 사이)
- 접힌 상태(기본): `▸ 입출력 형식`, 출처 배지(둥근 테두리: 직접 정의함=파란색, 예제로 추론함=주황색. 확장에 넣은 형식 데이터는 배지 없음), 시그니처 `solution(a: int, b: int) → int`(고정폭 12px, 넘치면 말줄임).
- 머리 줄 오른쪽 끝 형식 상태 아이콘(24px 버튼, 펼쳤을 때 늘, 접혔을 때는 경고가 있을 때만): 예제와 안 맞으면 노란 삼각형 느낌표, 맞으면 체크(`--pass`). 마우스를 올리거나 포커스하면 아이콘 아래 오른쪽 정렬 말풍선(최대 420px, 카드에 잘리지 않게 화면 기준 위치)에 메시지를 보인다: 경고 목록(최대 5개, "예제 1 입력: …", 저장한 형식이 안 맞아 쓰지 않았으면 그 이유가 먼저) 또는 "예제 N개를 모두 이 형식으로 읽고 다시 쓸 수 있어요." 메시지를 본문에 바로 보이지 않는다.
- 펼친 상태: 코드 영역 높이에서 96px을 뺀 만큼까지 커지고 넘치면 스크롤한다. 순서는
  1. 안내(추론한 형식이면 "예제와 문제 설명으로 추론한 형식이에요. 틀렸다면 고쳐서 저장해 주세요.")
  2. 표(JSON 편집은 없다. 표로 DSL v1을 모두 표현한다). 행 하나가 매개변수 하나이고, 입력을 읽는 순서가 곧 `solution` 매개변수 순서다.
     - 열 너비는 고정이다(`table-layout: fixed`): 매개변수 104px, 타입 100px, 읽는 방법(나머지), 줄 84px, 순서·삭제 72px. 타입이나 읽는 방법을 바꿔도 열이 움직이지 않는다. 입력·선택 상자는 모두 높이 24px, 행 높이 32px.
     - 매개변수 이름(입력, 열 너비를 채움, Enter나 포커스 이동 때 적용, 개수에서 참조한 이름도 함께 바뀜). 비었거나 쓸 수 없는 이름(예약어, 대문자로 시작), 다른 매개변수와 같은 이름이면 칸 테두리가 빨갛고(`--fail`, `aria-invalid`) 마우스를 올리면 이유를 보인다. 같은 이름은 경고 목록에 한 번만 적는다
     - 타입(선택, 열 너비를 채움, `int`, `line[]`처럼 이름만)
     - 읽는 방법: 선택 상자(116px) '새 줄에서' / '같은 줄에서' / '여러 줄에서' / '끝내는 줄까지' / '입력 끝까지'(마지막 매개변수이고 입력 반복이 '한 번'일 때만). 배열은 다섯 가지, 2차원 배열과 `line[]`은 뒤의 세 가지, 나머지는 앞의 두 가지. 고를 것이 하나뿐이면(첫 행의 단일 값) 흐린 글자로 고정한다. 마우스를 올리면 뜻을 보인다("끝내는 줄이 나올 때까지 한 줄에 하나씩 읽어요. 끝내는 줄은 값에 넣지 않아요" 등). 그 오른쪽에 라벨과 입력 칸(68px): 한 줄의 1차원 배열은 '개수'(비우면 줄 끝까지), '여러 줄에서'는 '줄 수'(2차원 배열은 '행'), '끝내는 줄까지'는 '끝'(예: 0, -1 -1), 2차원 배열은 '열'(비우면 줄 전체). 개수는 숫자나 앞에서 읽은 정수로 된 식(`n`, `n-1`, `2*n-1`, `n*m`, `2*(n+m)`). 개수를 적은 1차원 배열은 체크 상자 '여러 줄에 걸침'(flow), `line`과 `line[]`은 '빈 줄·공백 그대로'(raw)를 함께 보인다. 끝 칸에 마우스를 올리면 `<0`, `<=0`, `#*` 같은 끝 조건도 안내한다.
     - 줄: 입력에서 읽는 위치("1번째 줄", "2번째 줄부터", 여러 줄 뒤는 "그다음 줄", "그다음 줄부터"). 블록에서 읽는 매개변수는 "블록 (n번째 줄부터)". 카드 너비가 600px 이하면 이 열을 숨긴다.
     - 블록(여러 줄을 되풀이해 읽는 묶음): 첫 매개변수 위에 머리 행을 둔다. 타입 열부터 '블록', 횟수나 끝내는 줄 입력 칸(입력 끝까지면 없음), "번 반복해 읽어요. 아래 매개변수는 블록마다 값이 하나씩 모여 배열이 돼요. 블록에 넣고 빼는 것은 아직 표에서 할 수 없어요."(12px). 블록 안 매개변수는 '입력 끝까지'를 고를 수 없고, 블록의 첫 매개변수는 앞 행과 같은 줄에 둘 수 없다.
     - 행 끝 아이콘 버튼 ↑ ↓ ×(위로, 아래로, 삭제). 모두 지우면 "입력이 없는 문제예요. solution()을 매개변수 없이 불러요."가 보인다.
     - 마지막 행 아래 매개변수 열에 점선 테두리 `+` 버튼(매개변수 입력 칸과 같은 크기, 최대 16개, 이름은 n, m, k… 중 안 쓴 것, int, 새 줄).
     - '입력 반복' 행: 한 번 / 첫 줄의 수만큼 / 입력이 끝날 때까지 / 끝내는 줄까지(끝내는 줄 입력, 예: 0 0).
     - '반환값' 행: 타입(타입 열), 그리고 배열이면 구분자(한 줄에 공백으로 구분/한 줄에 하나씩, 2차원은 열 사이 공백/없음), bool이면 참·거짓 문구, double이면 소수 자리 수, `line[]`이면 "원소마다 한 줄씩 그대로 출력".
     - '케이스 출력' 행(입력 반복이 '한 번'이 아닐 때): '케이스 머리말' 입력 칸(128px, 자리 표시 `Case #{i}: `, `{i}`는 케이스 번호, 끝에 `\n`을 쓰면 머리말만 한 줄)과 '케이스 뒤 빈 줄' 체크 상자. 입력 반복을 '한 번'으로 바꾸면 머리말은 지운다.
  3. 버튼(결과 패널 버튼 모양): 저장(주 버튼, 통과하고 바뀐 것이 있을 때만), 형식 초기화(직접 정의한 형식일 때), 형식 오류 신고(새 탭, 문제 번호·지금 쓰는 형식·출처·버전만 담은 `4-format.yml` 이슈. 예시 문제에서는 없다)
  4. 상태 문구(`role=status`): "형식을 저장했어요. 이 문제는 이제 이 형식으로 풀어요." 등
- 편집할 때마다 예제 검증(ADR-0006 3단계)을 다시 한다.
- 저장하면 출처가 '직접 정의함'이 되고, 손대지 않은 시작 코드는 새 시그니처로 바뀐다.

**파일 탭**: solution 함수 모드에서는 `solution.js`, `solution.py`, `solution.cpp`, `Solution.java`.

**테스트 케이스 추가 (solution 함수 모드)**
- 열: `#`, 매개변수마다 하나(머리글에 이름과 타입), `기댓값`(반환 타입), 삭제.
- 안내: "예제 N개 다음에 실행됩니다. 값은 `3`, `[1, 2, 3]`, `"abc"`, `[["#", "."]]`처럼 적어 주세요."
- 예제 행은 매개변수 값으로 풀어 보인다(한 케이스로 읽을 수 없으면 입력 그대로).
- 확인을 누르면 칸마다 검사해 틀린 칸은 빨간 테두리와 아래 빨간 글자("정수가 필요해요", "'arr'의 길이가 3이에요. n = 2과(와) 같아야 해요")로 알리고 닫지 않는다.
- 저장은 표준 입출력으로 한다(실행 경로는 그대로). 형식에 맞지 않는 예전 케이스는 입력 그대로 보이고 그대로 실행한다.

**실행·제출**: 사용자 코드 + 입출력 코드를 실행하고 제출한다. 오류 줄 번호는 사용자 코드 기준으로 바꾸고, 입출력 코드 안의 오류는 "입출력 코드에서 오류: 형식이 예제와 맞지 않을 수 있어요." 또는 "solution 함수의 이름, 매개변수, 반환 타입이 입출력 형식과 맞는지 확인해 주세요."로 알린다. 방화벽 검사는 합친 코드로 한다.

## 7.3 제출 기록 (M7, ADR-0012)

문제 영역 맨 위의 탭: '문제 설명', '제출 기록'. 결과 영역 탭(실행 결과·채점 결과)과 같은 모양이다(14px 굵게, 고른 탭은 흰 글자와 파란 밑줄 2px, 아래 1px 구분선). 탭을 바꿔도 문제 본문은 숨기기만 해서 번역·수식이 그대로 남는다. 예시 문제(번호 없음)에는 '제출 기록' 탭이 없다.

**도구 줄** (안쪽 여백 12px 16px, 아래 10px 간격)
- 왼쪽: 보기 전환 '내 제출 | 맞힌 사람 | 숏코딩'. 둥근 바탕(반경 8px, 안쪽 3px) 안의 버튼(13px 굵게, 반경 6px), 고른 것은 밝은 바탕과 흰 글자. 처음에는 '내 제출'.
- 오른쪽: '맞힌 사람'·'숏코딩'에서 언어 필터(높이 30px, 너비 120~220px로 고른 이름과 화살표가 겹치지 않고 긴 이름은 말줄임, '모든 언어', '현재 언어 (node.js)'처럼 편집기 언어의 백준 이름, 그다음 백준의 묶음 C++·Java·Python·C·Rust와 자주 쓰는 언어를 알파벳순으로), 새로 고침 아이콘 버튼, 백준에서 보기 아이콘 링크(지금 보기의 백준 페이지를 새 탭으로). 아이콘 버튼은 30px 정사각형, 반경 6px, 마우스를 올리면 바탕이 진해진다.

**불러오기**: 보기를 처음 열 때 그 첫 페이지를 읽는다(제출 기록 탭을 열면 '내 제출'만). 백준이 스크립트 요청에 빈 페이지를 돌려주므로 확장이 그 페이지를 문제 탭 바로 옆의 비활성 탭으로 잠깐 열어 읽고 닫는다(ADR-0012). 한 번에 한 페이지, 1초 이상 간격. 표에 한 페이지(20줄)보다 많이 들어가면 다 찰 때까지 다음 페이지를 이어서 읽는다. 같은 목록은 1분 동안 다시 읽지 않는다. 언어를 바꾸면 그 조건의 첫 페이지를 읽는다.

**표** (보기 높이를 채운다)
- 13px, 줄 높이 36px 고정(머리글 32px, 12px 굵게 안내색), 줄마다 아래 1px 구분선, 칸 좌우 여백 6px(칸 사이 12px), 넘치면 말줄임. 정렬: 누가·무엇으로(아이디·언어·결과)는 왼쪽, 잰 값(순위·시간·메모리·코드 길이·제출)은 머리글과 함께 오른쪽. 숫자 폭을 맞추고 단위는 11px 안내색, 값이 없으면 '—'. 메모리는 999,999KB까지, 그 위는 MB(정수). 코드 길이는 9,999B까지, 그 위는 KB(100KB 미만은 소수 한 자리)라 숫자는 네 자리를 넘지 않는다.
- 열과 너비(가장 긴 값 기준, 여백 포함): 순위 56, 아이디 112(넘치면 말줄임), 결과 76, 언어 120('Java 8 (OpenJDK)'), 빈칸(남는 폭), 시간 74('99,999ms'), 메모리 86('999,999KB'), 코드 길이 60('9,999B'), 제출 66('11개월 전'), 코드 40. 내 제출은 결과·언어·빈칸·시간·메모리·코드 길이·제출, 맞힌 사람은 순위·아이디·언어·빈칸·시간·메모리·코드 길이·제출, 숏코딩은 순위·아이디·언어·빈칸·코드 길이·시간·메모리·제출. 제출 번호는 보이지 않는다. 영역을 넓히면 언어와 숫자 사이 빈칸만 넓어진다. 아이디는 누르면 백준 사용자 페이지(`https://acmicpc.net/user/{아이디}`)가 새 탭으로 열린다(줄의 코드 보기와 따로; 평소에는 글자색, 마우스를 올리면 링크색 밑줄).
- 좁아질 때: 빈칸이 먼저 줄고, 표 폭이 모든 열의 합보다 작아지면 보기마다 덜 필요한 열부터 하나씩 숨긴다. 내 제출은 코드 길이(522px 미만) → 제출(462px) → 메모리(396px). 맞힌 사람은 코드 길이(614px) → 제출(554px) → 메모리(488px) → 순위(402px). 숏코딩은 제출(614px) → 메모리(548px) → 시간(462px) → 순위(388px). 376px 미만이면 아이디 96·언어 100, 336px 미만이면 결과 72·아이디 84·언어 92·시간 66으로 좁힌다(문제 영역 최소 320px에서도 코드 칸까지 보인다).
- 마지막 칸(40px): 코드를 볼 수 있는 줄은 링크색 코드 아이콘(`</>`, 선 2.2px)을 링크색 바탕(다크 30%, 라이트 14%)의 둥근 사각형(24×22px, 반경 6px)에 넣고, 마우스를 올리면 링크색 채움에 흰 아이콘. 작성자가 공개하지 않은 줄은 같은 모양의 노란 자물쇠(선 2px, 에러와 같은 노랑). 코드를 볼 수 있는 줄은 마우스를 올리면 바탕이 뚜렷하게 바뀌고(다크 `#34495E`, 라이트 `#E8F0FA`) 커서가 손 모양이며, 누르거나(Enter·Space) 하면 '한 제출'이 열린다. 내 제출은 모두 열린다.
- 결과: 아이콘이 붙은 둥근 칩(너비 60px로 모두 같고, 12px 굵게, 줄 높이 20px, 색의 옅은 바탕). 문구는 두 글자: 정답(체크), 오답(×), 초과(시간은 시계, 메모리는 칩, 출력은 줄 아이콘), 형식(출력 형식), 에러(런타임은 경고, 컴파일은 `<>`), 부분 점수는 'N점', 채점 중은 'N%' 또는 '채점', 대기, 불가, 없음. 색: 정답 초록(다크 `#3ECF8E`, 라이트 `#12875A`), 오답·초과·형식 빨강(`--fail`), 에러 노랑(다크 `#F5B83D`, 라이트 `#A15C00`), 부분 점수 링크색, 그 밖은 `--out-hint`. 남색 패널에서 묻히지 않는 밝기를 고른다. 백준의 문구(예: "런타임 에러 (OutOfBounds)")는 툴팁으로 보인다.
- 제출: 백준처럼 "방금", "5분 전", "3시간 전", "2일 전", "4개월 전", "3년 전". 마우스를 올리면 툴팁에 `2026년 11월 25일 14:03:05`. 이 칸이 남는 폭을 차지해 잘리지 않고, 언어 칸은 96px로 고정한다.
- 페이지: 스크롤바가 생기지 않도록 표 높이에 들어가는 줄 수만큼 한 페이지에 보인다(창 크기를 바꾸면 다시 센다). 표 아래 가운데 '‹ 이전', 쪽 번호, '다음 ›'(높이 28px, 테두리 없는 글자 버튼, 위 4px·아래 14px 여백). 불러온 줄을 넘어가면 백준의 다음 페이지를 읽는다. 마지막 페이지에서 '다음'은 비활성, 한 페이지뿐이면 숨긴다.
- 처음 불러올 때, 새로 고침, 다 차지 않은 페이지가 다음 페이지를 기다릴 때는 줄을 그리지 않고 표 머리 아래 가운데에 도는 원과 "백준에서 불러오는 중"만 보인다.
- 실패 문구(13px `--fail`, `role=alert`): 열지 못함, 응답 없음(20초), 읽는 탭이 닫힘, 모양이 달라 읽지 못함, 확장과 연결 안 됨.
- 빈 상태: "아직 이 문제에 낸 제출이 없어요."(내 제출), "이 조건으로 맞힌 사람이 없어요."(맞힌 사람), "이 조건의 숏코딩 기록이 없어요."(숏코딩).

**내 제출**: 백준 채점 현황의 내 제출(`/status?problem_id=…&user_id={아이디}`)을 백준 순서(최신순)로 보인다. 확장은 제출 기록을 따로 저장하지 않는다. 아이디는 백준 페이지 머리글의 로그인 아이디(문제 페이지를 열 때 기억한 것)이고, 모르면 "백준 아이디를 몰라 내 제출을 불러오지 못했어요. 백준에 로그인한 뒤 문제 페이지를 새로고침해 주세요." 제출하면 목록을 다시 읽는다.

**맞힌 사람·숏코딩**: 이 문제의 맞힌 사람(`/problem/status/…`, 실행 시간순)과 숏코딩 순위(`/short/status/…`, 코드 길이순)를 백준과 같은 순서로 보인다.

**한 제출** (줄을 누르면 목록 대신, 안쪽 여백 12px 16px)
- 맨 위 한 줄: 왼쪽 '목록으로' 아이콘 버튼(‹), 결과 칩, 언어(15px 굵게), 다른 사람 제출이면 '· 아이디'. 오른쪽에 '편집기로 불러오기'(링크색 테두리 버튼, 내려받기 아이콘), '복사'(테두리 버튼, 누르면 "복사했어요"), 백준에서 보기 아이콘 링크.
- 그 아래 네 칸 요약(반경 8px, 칸 사이 1px 선): 메모리, 시간, 코드 길이, 제출(작은 이름 11px 안내색, 값 14px 굵게). 좁으면 두 줄 두 칸.
- 코드: 편집기와 같은 테마·글꼴·구문 색, 줄 번호, 읽기 전용(선택·복사는 된다). 남은 높이를 채우고 넘치면 스크롤한다(반경 8px, `--pre-bg`).
- 코드 출처: 열 때 백준 소스 페이지를 비활성 탭으로 읽는다("백준에서 코드를 불러오는 중"). 로그인하지 않았으면 "코드를 보려면 백준에 로그인해야 해요."
- 편집기로 불러오기: 그 제출의 언어로 바꾸고 표준 입출력 모드로 코드를 넣는다(백준은 전체 프로그램을 보관한다). 확장이 지원하지 않는 언어(예: C++17 (Clang))면 버튼이 없다. 바뀔 코드가 비었거나 시작 코드이거나 같은 코드면 바로 넣고, 아니면 대화상자로 묻는다: 제목 "코드 불러오기", 본문 "편집기의 {언어} 코드를 이 제출의 코드로 바꿉니다. 지금 작성한 코드는 사라집니다. 불러오시겠습니까?", 버튼 취소·불러오기. 넣은 뒤 실행 결과 탭에 "제출 기록의 코드를 불러왔습니다."
- 클립보드가 막히면 "복사하지 못했어요. 코드를 드래그해 선택한 뒤 Ctrl+C로 복사해 주세요."

## 8. 시험 화면

M4 모의 시험(ADR-0005, #101)의 화면이다. 참고 화면을 직접 측정하지 않았고, 풀이 화면(1~7장, 9~10장)의 값과 테마를 그대로 쓴다. `exam.html`의 주소로 화면을 나눈다.

| 주소 | 화면 |
|---|---|
| `#setup`, `#setup?include={문제}` | 시험 만들기. 팝업 '모의 시험' 탭과 같은 폼을 한 장 페이지(가운데, 폭 440px)로 보인다. `include`가 있으면 그 문제를 '포함할 문제'에 넣은 채로 연다(뺄 수 있다) |
| `#{시험 id}` | 시험 화면 |
| `#{시험 id}/result` | 결과 화면 |

**시험 만들기 폼** (팝업 탭과 공용 컴포넌트)
- 카드 '난이도': 브론즈·실버·골드·플래티넘 칩. 여러 개를 고르되 언제나 이어진 범위다(바깥 칩을 누르면 범위가 늘고, 양 끝 칩을 누르면 줄고, 가운데 칩을 누르면 그 하나만 남는다). 기본 실버~골드.
- 카드 '알고리즘 (선택 안 하면 전체)': 구현, 그리디, DP, 그래프, BFS·DFS, 문자열, 이분 탐색, '+ 더보기'(정렬, 브루트포스, 수학, 자료 구조, 백트래킹, 최단 경로, 시뮬레이션, 누적 합, 두 포인터, 트리). 고른 것 중 하나라도 있으면 된다(OR).
- 카드: 문제 수(1~8, 기본 4, −/+), 제한 시간 칩 60분·90분·120분(기본)·직접(10~300분 입력, 범위 밖이면 시작이 꺼짐), 스위치 '이미 푼 문제 빼기 @아이디'(기본 켬, 아이디를 모르면 꺼지고 이유를 보인다).
- 카드 '포함할 문제 (선택)': 넣은 문제 번호를 칩("1000번 ×", 누르면 빠짐)으로 보이고, 아래 번호 칸과 '추가'(Enter도 추가). 1~9999999의 정수만, 같은 번호는 한 번만, 틀리면 칸 아래 빨간 글자. 넣은 문제 수가 문제 수와 같으면 칸과 '추가'가 꺼지고 "문제 수를 늘리면 더 추가할 수 있어요". 문제 수 −는 넣은 문제 수 아래로 내려가지 않는다(꺼진 버튼의 툴팁 "포함한 문제보다 적게 할 수 없어요"). 팝업은 빈 목록, 백준 메뉴는 그 문제 하나로 시작한다.

- 칩: 높이 30px, 반경 999px, 테두리 1px. 고른 칩은 강조색 배경·흰 글자.
- 팝업 탭 아래에는 '지난 시험'(최근 5개): "11/22 · 실버~골드 4문제"와 "3/4" 또는 '진행 중'. 누르면 결과 화면(진행 중이면 시험 화면)을 연다.
