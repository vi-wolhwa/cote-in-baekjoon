# 풀이 화면 디자인 명세

PRD 8장 결정에 따라 풀이 화면을 기업 코딩테스트 풀이 화면(프로그래머스 연습 화면)과 같게 만든다.

- 이 문서의 값은 2026-11-23에 1440×900 화면에서 로그인 없이 실제 화면의 계산된 스타일을 측정한 것이다.
- 그쪽의 이미지·스타일시트·스크립트 파일은 쓰지 않는다. 이 값으로 직접 구현한다.
- 이름·로고·아이콘은 쓰지 않는다.
- 측정하지 못한 항목은 **[미확인]** 으로 표시했다.

## 3. 글꼴

- **UI**: `Inter, NotoSansKR, "Helvetica Neue", Helvetica, Arial, "맑은 고딕", sans-serif`
- **문제 본문**: 16px, 줄 높이 28.8px, 자간 −0.1px. h4 16px 굵게, h5 15px.
- **고정폭**: `Hack, Menlo, Monaco, Consolas, monospace`
  - 에디터 16px, 줄 높이 22.4px
  - 결과 14px, 줄 높이 1.5
  - 코드 블록 14px

## 4. 에디터 동작

- 줄 번호, 자동 줄바꿈, 탭 크기 4, 들여쓰기 4칸(공백), 현재 줄 강조, 괄호 짝 표시, 괄호 자동 닫기
- 키맵: 기본 `sublime`, `vim`, `emacs` 중 선택. 선택은 저장해서 유지한다.
  - sublime: 선택 영역에서 Tab은 들여쓰기, Shift-Tab은 내어쓰기
- 파일 탭 이름: `solution.<확장자>`
- 언어 선택: 목록에서 고른다. 이 제품은 백준 언어 ID에 맞춘다 (PRD 6장 순서).

## 5. 버튼과 대화상자

**하단 바 순서**
- 왼쪽: 질문하기(백준 질문 게시판 링크, 테스트 케이스 추가하기와 같은 어두운 버튼), 테스트 케이스 추가하기
- 오른쪽: 초기화, 코드 실행, 제출하기(주 버튼)
- 질문하기·다른 사람의 풀이는 백준의 질문 게시판·맞힌 사람 링크로 대신할지 M1에서 정한다.

**초기화 대화상자**
- 제목: 초기화 안내
- 본문: "지금까지 작성한 모든 코드가 삭제되고 문제를 처음 시작했을 때의 상태로 돌아갑니다. 초기화 하시겠습니까?"
- 버튼: 취소, 확인
- 확인 후 결과 창: "코드를 초기화하였습니다."

**테스트 케이스 추가**
- 제목: 테스트 케이스 추가
- 표준 입출력 문제는 Input / Output 열을 쓴다.
- 배치는 **[미확인]** 이다.

**실행 중**: 중지 버튼이 나타나고, 중지하면 "실행 중단"을 표시한다.

## 6. 실행 결과 출력 형식

- 구분 기호는 "〉"(U+3009, 불투명도 32%)다.
- 라벨은 오른쪽 정렬된 10rem 폭 열에 `#44576C`로 쓴다.
- 빈 상태: "실행 결과가 여기에 표시됩니다."

```
테스트 1
     입력값 〉 1 2
     기댓값 〉 3
   실행 결과 〉 테스트를 통과하였습니다.
        출력 〉 (표준 출력이 있을 때만)
```

**통과·실패 문구**
- 통과는 파란색이다.
- 실패는 빨간색으로 "실행한 결괏값 X이(가) 기댓값 Y와(과) 다릅니다."를 표시한다.

**요약**
- "테스트 결과 (~˘▾˘)~" 제목 뒤에 "N개 중 M개 성공"을 쓴다. 모두 통과하면 파란색, 아니면 빨간색이다.
- 모두 통과하면 다음 안내를 덧붙인다: "샘플 테스트 케이스를 통과했다는 의미로, 작성한 코드가 문제의 정답은 아닐 수 있습니다."

**오류**
- 런타임 에러: 빨간 제목 "런타임 에러", 그 아래 표준 에러 내용
- 상태 문구: 실패, 시간 초과, 메모리 초과, 런타임 에러, 출력 크기 초과
- 시간 초과 설명: "실행 시간이 N초를 초과하여 실행이 중단되었습니다. 실행 시간이 더 짧은 다른 방법을 찾아보세요."

**채점 결과** (제출 후, 백준 결과를 이 형식으로 보여 준다)
- "채점을 시작합니다." 뒤에 결과 줄이 나온다. 예: `정확성 테스트 〉 맞았습니다!! (12ms, 11.2MB)`

## 7. 문제 영역

- 안쪽 여백 16px, 영역 안에서 세로로 스크롤한다. 맨 위에 '문제 설명' 라벨이 있다.
- 섹션 사이에 `hr`(1px `#172334`, 위아래 24px)을 둔다.
- 표: 셀 `#202B3D`, 테두리 1px `#172334`, 안쪽 여백 4px 12px
- 코드 블록: 배경 `#202B3D`, 안쪽 여백 20px 24px, 반경 4px
- 백준 문제는 섹션 순서대로 표시한다: 문제, 입력, 출력, 제한, 예제 입력·출력, 힌트

## 8. 시험 화면

M4 모의 시험(ADR-0005, #101)의 화면이다. 참고 화면을 직접 측정하지 않았고, 풀이 화면(1~7장, 9~10장)의 값과 테마를 그대로 쓴다. `exam.html`의 주소로 화면을 나눈다.

| 주소 | 화면 |
|---|---|
| `#setup`, `#setup?include={문제}` | 시험 만들기. 팝업 '모의 시험' 탭과 같은 폼을 한 장 페이지(가운데, 폭 440px)로 보인다. `include`가 있으면 맨 위에 "N번 문제를 넣고 나머지를 골라요." |
| `#{시험 id}` | 시험 화면 |
| `#{시험 id}/result` | 결과 화면 |

**시험 만들기 폼** (팝업 탭과 공용 컴포넌트)
- 카드 '난이도': 브론즈·실버·골드·플래티넘 칩. 여러 개를 고르되 언제나 이어진 범위다(바깥 칩을 누르면 범위가 늘고, 양 끝 칩을 누르면 줄고, 가운데 칩을 누르면 그 하나만 남는다). 기본 실버~골드.
- 카드 '알고리즘 (선택 안 하면 전체)': 구현, 그리디, DP, 그래프, BFS·DFS, 문자열, 이분 탐색, '+ 더보기'(정렬, 브루트포스, 수학, 자료 구조, 백트래킹, 최단 경로, 시뮬레이션, 누적 합, 두 포인터, 트리). 고른 것 중 하나라도 있으면 된다(OR).
- 카드: 문제 수(1~8, 기본 4, −/+), 제한 시간 칩 60분·90분·120분(기본)·직접(10~300분 입력, 범위 밖이면 시작이 꺼짐), 스위치 '이미 푼 문제 빼기 @아이디'(기본 켬, 아이디를 모르면 꺼지고 이유를 보인다).
- 흰 '시험 시작' 버튼(라이트 테마의 시험 페이지에서는 파란 버튼). 누르는 동안 "문제를 고르는 중…". 실패 이유는 버튼 아래 빨간 글자.
- 칩: 높이 30px, 반경 999px, 테두리 1px. 고른 칩은 강조색 배경·흰 글자.
- 팝업 탭 아래에는 '지난 시험'(최근 5개): "11/22 · 실버~골드 4문제"와 "3/4" 또는 '진행 중'. 누르면 결과 화면(진행 중이면 시험 화면)을 연다.

**시험 화면** (2026-11-24 제품 책임자 요청: 문제 번호는 문제 왼쪽의 세로 레일, 실제 코딩테스트 화면처럼)

| 위치 | 구성 |
|---|---|
| 상단 바(47px, 두 테마 모두 어두움) | 왼쪽 "모의 시험 〉 실버~골드 4문제". 오른쪽 안내 "결과는 시험이 끝나면 공개"와 빨간 '시험 종료'(배경 `#D32F2F`, 흰 글자 600, 반경 4px) |
| 왼쪽 문제 레일(64px) | 상단 바 바로 아래부터 창 아래 끝까지, 문제 영역 왼쪽. 오른쪽 사이드바와 짝을 이룬다: 배경 다크 `#263747`·라이트 `#FFFFFF`, 오른쪽 테두리 1px(다크 `#172334`, 라이트 `#D7E2EB`). 문제가 많으면 레일 안에서 세로로 스크롤 |
| 문제 버튼 | 1번부터 위에서 아래로. 40×40 모서리 둥근 사각형(반경 8px), 간격 12px, 가운데 정렬, 레일 위에서 16px. 글자 16px 600. 기본 배경 다크 `#44576C`·흰 글자, 라이트 `#E9ECF3`·`#263747` 글자. 호버 다크 `#56697F`, 라이트 `#D7E2EB`. 지금 문제는 `#0078FF` 채움·흰 글자, `aria-current="step"`. 키보드 초점은 강조색 2px 링. 위·아래 화살표로 문제를 옮긴다(목록 안에서, 지금 문제 버튼만 Tab 순서에 있음) |
| 문제 버튼 표시 | 제출한 문제: 오른쪽 아래 모서리에 겹친 16px 초록 원(`#1FAB5A`)과 흰 체크, 레일 배경색 2px 테두리. 결과는 숨긴 채 '제출함'만 뜻한다. 다시 볼 문제: 오른쪽 위 모서리에 16px 노란 원(`#FFC857`)과 남색 깃발. 둘 다 함께 보일 수 있다. 이름·툴팁은 "1번 문제 · 제목 · 제출함 · 다시 볼 문제" |
| 제목 줄 | "1번"(강조색 700) + 문제 제목. 오른쪽에 '다시 볼 문제' 토글(깃발 아이콘, 켜면 노란 테두리·글자)과 언어 선택 |
| 가운데 | 풀이 화면과 같다: 문제(처음 열 때 백준 문제 페이지를 뒤쪽 탭으로 열어 읽음, "문제를 불러오는 중입니다…", 20초가 넘거나 실패하면 이유와 '다시 시도'), 에디터, 실행 결과. 아래 탭은 '실행 결과'와 '제출' |
| 하단 바 | 왼쪽 '+ 테스트 케이스 추가하기'. 오른쪽 초기화, 코드 실행(실행 중에는 실행 중지), 제출하기. 시간이 끝나면 제출하기가 꺼진다 |
| 오른쪽 사이드바(64px) | 맨 위 모래시계 아이콘, "남은 시간"(10px), `h:mm:ss`(12px 700, `tabular-nums`, 강조색). 5분 이하면 빨강(다크 `#FF7B7B`, 라이트 `#D32F2F`). 구분선 아래 테마 전환 |

- '제출' 탭은 채점 결과를 보이지 않는다. 제출 뒤에는 "제출했습니다. 결과는 시험이 끝나면 공개됩니다."와 마지막 제출(시작 후 시각, 언어)만 보인다.
- 제출 창의 채점 현황 페이지는 같은 문구로 화면 전체를 덮는다(배경 `#263747`). 결과를 읽으면 창은 평소처럼 닫힌다.
- '시험 종료'는 확인 대화상자("시험을 끝낼까요? …", 제출하지 않은 문제 수, '계속 풀기'·빨간 '시험 종료')를 거친다. 남은 시간이 0이 되면 묻지 않고 끝난다. 둘 다 결과 화면으로 간다.
- 코드는 연습과 같은 `code:{문제}:{언어}`에 저장한다. 문제를 옮기면 에디터를 새로 만들어 되돌리기 기록이 섞이지 않는다.
