# ADR-0009: CI 속도

- 상태: 승인 (2026-11-24)
- 관련: `.github/workflows/ci.yml`, `scripts/ci/e2e-select.ts`

## 배경

CI는 작업 하나에서 린트, 타입 검사, 단위 테스트, 빌드, E2E 84개를 차례로 돌려 약 6분이 걸렸다. E2E가 약 3분, 단위 테스트가 약 1분 45초였다. 단위 테스트는 실제 엔진(clang, TeaVM, Pyodide)을 띄우는 파일 몇 개가 대부분을 차지했다. 제품 책임자가 CI 시간을 줄이라고 요청했다(2026-11-24).

## 결정

- **병렬 작업**: 변경 범위, 린트·타입·빌드, 단위 테스트(2조각), E2E(최대 3조각)를 동시에 돌린다. Playwright `--shard`, Vitest `--shard`를 쓴다. E2E 조각 수는 고른 스펙 수에 맞춘다(2개 이하 1조각, 5개 이하 2조각, 그 밖과 전체 3조각). 조각마다 설치·빌드·브라우저 준비를 따로 하므로, 스펙이 적을 때 남는 조각이 준비만 하고 끝나지 않게 한다(2026-11-25).
- **바뀐 영역의 E2E만**
  - 풀 리퀘스트는 바뀐 파일로 E2E 스펙을 고른다(`scripts/ci/e2e-select.ts`).
  - 파일마다 첫 번째로 맞는 규칙을 쓴다: E2E 없음(문서, 단위 테스트, 개발 스크립트), 영역의 스펙들(예: `src/runner/cpp/` → cpp·languages·solution), 전체.
  - 어느 규칙에도 없는 파일(공용 코드, 설정, 패키지)은 전체를 돌린다. 새 영역을 놓치지 않기 위해서다.
  - 새 영역을 만들면 규칙도 함께 넣는다. 형식 데이터(`public/formats/`)는 solution·exam, 제출 기록 탭은 history 스펙만 돌린다. 아이콘·라이선스 문서·개발 스크립트는 E2E를 돌리지 않는다.
  - main 푸시는 늘 전체를 돌려 선택이 놓친 회귀를 잡는다.
- **문서만 바뀌면** 단위 테스트와 E2E를 건너뛰고 린트(Prettier)만 돈다.
- **무거운 단위 테스트 파일 나누기**
  - solution 실행 테스트를 엔진별 파일(js, python, c, cpp 두 조각, java)로 나눠 병렬로 돌린다.
  - 엔진은 그 파일에서 처음 쓸 때 띄운다.
- **브라우저 캐시**: Playwright Chromium을 버전별로 캐시한다.

## 결과

- 풀 리퀘스트 대부분은 E2E 일부만 돌고, 전체를 돌 때도 조각마다 3분의 1씩 나뉜다.
- 선택 규칙이 틀리면 PR에서 회귀를 놓칠 수 있다. main 푸시의 전체 실행이 그물이다. 규칙은 `tests/e2e-select.test.ts`가 스펙 이름을 검사한다.
- 작업이 늘어 `npm ci`를 여러 번 한다(npm 캐시로 각 15초 안팎).
