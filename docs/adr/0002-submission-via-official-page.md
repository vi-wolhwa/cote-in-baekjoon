# ADR-0002: 제출은 공식 제출 페이지에서 사용자가 직접 한다

- 상태: 승인 (2026-11-24 #41로 일부 변경: 자동 제출 선택 기능)
- 날짜: 2026-11-23
- 관련: PRD 8.1, R1, 이슈 #2

## 배경

백준 [이용 규칙](https://help.acmicpc.net/rule)은 공식 `/submit` 경로에서 사용자가 직접 제출 버튼을 누르지 않는 모든 수단을 '자동 제출 도구'로 정의한다. 외부 프로그램, 스크립트, 대리 웹사이트가 예로 나온다. 적발 시 제재는 다음과 같다.

- 제출한 모든 소스 삭제
- 1회: 30일 제출 금지
- 2회: 사실상 영구 제출 금지

기술적으로는 다음이 모두 가능하다.
- `POST /submit/{id}` 요청을 직접 보내기 (CSRF 키를 읽어 폼 전송)
- 제출 버튼 자동 클릭

하지만 둘 다 규칙 위반이다. 사용자 계정이 제재를 받는다.

## 결정

1. 풀이 화면의 **제출하기**를 누르면 `https://acmicpc.net/submit/{id}`를 풀이 화면 창의 오른쪽 위에 겹치는 **작은 팝업 창**으로 연다(#35). 팝업을 열 수 없으면 새 탭으로 연다. (2026-11-24부터는 백그라운드 탭: 아래 '변경: 팝업 창 대신 백그라운드 탭')
   - `www.acmicpc.net`은 `acmicpc.net`으로 리디렉션되므로 `www` 없는 주소를 쓴다.
   - 로그인하지 않았으면 백준이 로그인 페이지를 거쳐 같은 탭의 제출 페이지로 돌려보낸다. 10분 안이면 그대로 채운다.
2. 그 페이지의 콘텐츠 스크립트가 언어와 코드를 채운다.
   - 코드는 백그라운드가 `chrome.storage.session`에 보관하고, 제출 페이지 콘텐츠 스크립트에 **메시지로** 넘긴다. 콘텐츠 스크립트에 session 저장소 접근 권한(`setAccessLevel`)을 열지 않는다.
   - 백그라운드는 보낸 쪽이 확장이 연 그 탭의 `/submit/{id}` 페이지인지 확인하고, 코드를 **한 번만** 넘긴 뒤 지운다. 새로고침이나 제출 실패로 페이지가 다시 열려도 사용자가 고친 코드를 덮어쓰지 않는다. 10분이 지나면 버린다.
   - 언어: `<select id="language">`의 값을 백준 언어 번호(node.js = 17)로 바꾸고 `change`, `chosen:updated` 이벤트를 보낸다. 이 select는 chosen.js(`#language_chosen`)로 꾸며져 있다.
   - 코드: 제출 페이지 에디터는 CodeMirror 5이고, 인스턴스는 페이지 자바스크립트 세계의 `.CodeMirror` 요소 속성(`el.CodeMirror`)에만 있다. 그래서 채우기는 `world: 'MAIN'` 콘텐츠 스크립트가 맡는다. 격리된 콘텐츠 스크립트와는 `CustomEvent`(JSON 문자열)로만 주고받고, MAIN 스크립트는 확장 API 없이 받은 언어와 코드를 검증해 채우기만 한다.
   - DOM에 기대는 코드는 `src/boj/submit-fill.ts` 한 곳에 모아 구조가 바뀌면 그 파일만 고친다.
3. 제출 버튼은 **사용자가 직접** 누른다. 확장은 클릭하지 않고, 폼을 제출하지 않고, 요청도 보내지 않는다.
   - 채운 뒤 배너로 안내한다: "언어와 코드를 채웠습니다. 내용을 확인하고 백준의 제출 버튼을 직접 눌러 주세요."
   - 채우기에 실패하면 코드를 클립보드에 복사한다. 사용자 동작 없이 복사가 막히면 배너의 **코드 복사** 버튼으로 복사하게 한다.
4. 제출 뒤 백준이 보여 주는 채점 현황 페이지에서 콘텐츠 스크립트가 결과를 읽는다.
   - 행: `#status-table tr[id^="solution-"]`. 결과는 `td.result span.result-text`의 글자와 `data-color`(없으면 `result-{코드}` 클래스), 메모리·시간은 `td.memory`, `td.time`, 제출 시각은 `[data-timestamp]`(유닉스 초)에서 읽는다.
   - 결과 코드는 백준 `App.result_colors()`와 같다. `wait`, `rejudge-wait`는 대기, `compile`, `judging`은 채점 중, 나머지(`ac`, `pe`, `wa`, `tle`, `mle`, `ole`, `rte`, `ce`, `del`, `pac`)는 최종 결과다.
   - 실시간 갱신: 백준 페이지가 스스로 받는 갱신(Pusher)이 행을 고치는 것을 `MutationObserver`로 관찰한다. 최종 결과가 나오거나 15분이 지나면 관찰을 멈춘다.
   - **갱신이 오지 않을 때(#35)**: 백준의 실시간 서버는 연결 한도를 넘으면 오류 4004로 연결을 거부한다. 그러면 백준 페이지도 "새로고침을 통해 채점 결과를 확인하세요"만 띄우고 결과를 갱신하지 않는다.
     - 이때 확장은 사용자가 방금 낸 **그 제출 1건**에 대해서만, 백준 페이지가 스스로 보내는 것과 같은 요청(`POST /status/ajax`, `solution_id`)을 보낸다.
     - 감시 중인 제출의 결과가 1초 동안 바뀌지 않을 때 시작한다. 간격은 0.7·0.7·1·1·1·1.5·2·3초 뒤 5초씩이다(#59에서 더 빠르게 조정).
     - 최종 결과가 나오면 멈추고, 최대 10분까지만 보낸다. 페이지가 결과를 스스로 갱신하면 다시 1초 뒤로 미룬다.
     - 제출 1건에 많아야 120여 번이고, 대부분 몇 번 안에 끝난다. 백준허브도 같은 방식(2~15초 간격, 10분 한도)으로 결과를 확인한다.
     - 받은 결과는 현황 표에도 써서 팝업에 진행 상황이 보이게 한다.
   - 대상: 로그인한 사용자(머리글의 `a.username`, 없으면 `from_mine=1` 주소의 `user_id`)가 **제출하기를 누른 뒤**(시계 오차 2분 허용) 그 문제에 낸 가장 최근 제출만 보고한다. 제출하기를 누른 뒤 1시간이 지나면 보고하지 않는다.
   - 읽은 결과는 `chrome.storage.local`의 `judge:{문제 번호}`에 저장하고, 풀이 화면은 저장소 변경을 구독해 표시한다.
5. **팝업 닫기와 복귀(#35, 2026-11-24에 백그라운드 탭으로 바뀜)**: 확장이 연 팝업 안에서 최종 결과가 나오면 결과를 0.3초 보여 준 뒤 팝업을 닫고 풀이 화면 탭과 창을 앞으로 가져온다. 풀이 화면은 '채점 결과' 탭에 결과를 보여 준다.
   - 사용자가 결과 전에 팝업을 닫으면 풀이 화면에 "제출 창이 닫혔습니다"를 표시한다.
   - 다른 탭이나 창에서 연 채점 현황은 결과만 보고하고 창을 건드리지 않는다.
6. **언어가 목록에 없을 때(#59)**: 백준은 사용자가 '사용할 언어'로 등록한 언어만 제출 페이지 목록에 보여 준다.
   - 선택한 언어가 목록에 없으면 코드를 그 탭에 다시 보관하고 언어 설정 페이지로 이동한다. 주소는 제출 페이지의 설정 링크를 우선 쓰고, 없으면 `/setting/language`를 쓴다.
   - 설정 페이지에는 이유와 '제출 페이지로 돌아가기' 버튼을 보여 준다.
   - 돌아오면 다시 채우고, 자동 제출이 켜져 있으면 제출한다.
   - 사용자 설정을 확장이 대신 바꾸지는 않는다.
7. 백준 방화벽이 막는 문자열이 코드에 있으면 제출 페이지 배너에 경고한다.
   - 목록은 백준허브(BaekjoonHub, MIT) `scripts/baekjoon/submitfilter.js`를 따른다. `document.cookie`, `document.write`, `.parentnode`, `.innerhtml`, `window.location`, `-moz-binding`, `<!--`, `-->`, `<![cdata[`와 `<script`, `<style`, `<svg`, `<iframe`, `<form`, `<set<` 같은 HTML 태그 모양 글자(OWASP CRS 941160)다. 백준허브가 '확인되지 않음'으로 표시한 항목은 뺐다.

## 변경: 자동 제출 선택 기능 (2026-11-24, #41)

제품 책임자가 자동 제출을 최우선 요구사항으로 정했다. 이 ADR의 "제출 버튼은 사용자가 직접 누른다"(결정 3)를 다음처럼 바꾼다.

- **기본으로 켜져 있다.** 개발 기간에는 제품 책임자가 자기 계정으로 검증하므로 따로 묻지 않는다(2026-11-24 제품 책임자 지시).
  - 하단 '자동 제출' 설정으로 끌 수 있다.
  - 웹스토어 배포 전에 검증 결과를 확인받고, 일반 사용자를 위한 기본값과 안내 방식을 다시 정한다(#44).
- **방식**: 채우기가 완전히 성공하면 1.2초 카운트다운(취소 가능) 뒤 페이지의 제출 버튼을 누른다.
  - 버튼 클릭이라 페이지의 정상 제출 경로를 그대로 탄다(CodeMirror 내용 반영, CSRF 필드 포함).
  - 제출 요청을 직접 만들어 보내지 않는다.
- **하지 않는 경우**: 아래 중 하나라도 해당하면 직접 제출 배너로 돌아간다.
  - 사람이 직접 풀어야 하는 보안 확인(reCAPTCHA v2 체크박스·그림 문제, hCaptcha, Cloudflare Turnstile)이 보일 때. **대신 풀거나 우회하지 않는다.**
  - reCAPTCHA v3는 멈춤 조건이 아니다(#45). 풀 문제가 없고, 백준 페이지가 스스로 토큰을 받아 정상 제출 경로에 붙인다. 백준은 토큰을 받는 동안 `#submit_preview`를 보여 주고 `#submit_button`을 숨긴다. 그래서 버튼이 보이고 눌릴 수 있게 될 때까지 최대 10초 기다린 뒤 누른다.
  - 방화벽 차단 문자열이 있을 때
  - 언어나 코드 채우기가 실패했을 때
  - 제출 버튼을 찾지 못했을 때
  - 사용자가 취소했을 때
- **위험**: 백준 규칙상 자동 제출 도구에 해당한다. 운영사 문의 결과에 따라 이 기능을 끄거나 바꾼다.

## 자동 제출을 다시 검토한 결과 (2026-11-24, #35)

제품 책임자가 '제출 탭을 오가는 흐름이 불편하다'며 자동 제출을 다시 검토해 달라고 요청했다.

- **기술적으로는 가능하다.**
  - 제출 버튼 클릭을 흉내 낼 수 있다.
  - CSRF 키를 읽어 `POST /submit`을 직접 보낼 수도 있다.
- **하지만 하지 않는다.** 백준 규칙은 공식 `/submit`에서 사용자가 직접 버튼을 누르지 않는 모든 수단을 자동 제출 도구로 본다.
  - 적발되면 그 사용자가 낸 **모든 소스가 삭제되고** 제출이 금지된다. 재범은 사실상 영구 금지다.
  - 공개 배포하면 이 위험을 확장을 설치한 모든 사용자가 진다.
- **차선책**으로 위 1·5번(팝업 창과 자동 복귀), 4번의 갱신 보완을 넣었다.
  - 사용자는 풀이 화면에서 제출하기를 누르고, 겹쳐 뜬 창에서 백준 제출 버튼을 한 번 누른다.
  - 그 뒤 결과를 보며 바로 코드를 고칠 수 있다.
- 백준이 허용하면 바꿀 수 있도록 운영사 문의에 '확장 화면에서 한 번에 제출'의 허용 여부도 함께 묻는다(`docs/ops/boj-inquiry.md`).

## 남은 위험

- **자동 입력**은 규칙에 명시되지 않은 회색 영역이다. 웹스토어 공개(M3) 전에 백준 운영사(데이원컴퍼니)에 문의한다.
  - 문의 초안은 Claude가 쓰고, 발송은 제품 책임자가 한다.
  - 허용되지 않으면 '코드를 클립보드에 복사하고 제출 페이지 열기'로 바꾼다. 이 동작은 설정 하나로 바꿀 수 있게 만든다.
- 백준 제출 페이지의 에디터 구조가 바뀌면 자동 입력이 깨진다. 실패하면 클립보드 복사로 자동 전환한다.

## 변경: 팝업 창 대신 백그라운드 탭 (2026-11-24)

제품 책임자 요청: "팝업 없이 백그라운드에서 문제를 채점하고 결과를 업데이트하라. 채점 중에는 빙글빙글 도는 로딩 표시로 알리고, 직접 확인하는 버튼으로 볼 수 있게 하라." 또 모의 시험 결과 화면에서 팝업을 실수로 닫으면 결과가 영영 갱신되지 않는 문제가 있었다. 위 결정 1·5를 다음처럼 바꾼다.

- **제출 탭**: 제출하기를 누르면 `https://acmicpc.net/submit/{id}`를 요청한 탭 바로 옆에 **비활성 탭**(`tabs.create({ active: false })`, 같은 창)으로 연다. 새 창은 열지 않고, 사용자는 지금 탭에 그대로 있다. 코드를 한 번만 넘기기, 언어·코드 채우기, 자동 제출(보안 확인은 우회하지 않음), 채점 현황의 결과 읽기(`MutationObserver`, `/status/ajax` 보완)는 그대로다.
- **상태**: 백그라운드가 `storage.session`의 `cib:submit-tab:{문제}`에 탭 id와 상태를 둔다: 제출 중(submitting) → 제출함(sent, 폼이 제출됨) → 채점 중(judging, 채점 현황이 보고) → 끝(done), 또는 직접 확인 필요(needs-user, 보안 확인·방화벽 문자열·언어 목록·채우기 실패·취소), 결과 전에 닫힘(closed). 제출 페이지 콘텐츠 스크립트가 자동 제출을 넘겨줄 때와 폼이 제출될 때 알린다.
- **닫기**: 최종 결과가 나오면 0.3초 뒤 그 탭을 닫는다. 아무것도 앞으로 가져오지 않는다(사용자는 자기 탭을 떠난 적이 없다).
- **화면**: 풀이 화면의 '채점 결과' 탭과 모의 시험 결과 화면에 도는 표시와 "제출 중"/"채점 중", 제출 탭을 앞으로 가져오는 **직접 확인** 버튼(`tabs.update(active)` + `windows.update(focused)`)을 보인다. 자동 제출이 멈추면 "직접 확인이 필요해요"와 강조한 직접 확인 버튼을 보인다. 언어 설정 우회(결정 6)는 그 탭 안에서 그대로 동작한다.
- **결과 다시 확인**: 최종 결과 전에 탭이 닫히면(실수, 브라우저 종료) "결과를 아직 못 받았어요"와 **결과 다시 확인** 버튼을 보인다. 누르면(사용자 클릭 때만) 그 문제를 제출 시각부터 다시 감시하고, 사용자 자신의 채점 현황 `https://acmicpc.net/status?problem_id={id}&user_id={아이디}`(아이디를 모르면 `from_mine=1`)를 백그라운드 탭으로 연다. 기존 채점 현황 콘텐츠 스크립트가 읽고 최종 결과가 나오면 탭을 닫는다. 1분 안에 아무것도 찾지 못하면 탭을 닫는다.
- **권한**: 새 권한이 없다. 확장이 연 탭을 만들고, 앞으로 가져오고, 닫는 데는 권한이 필요 없다. 팝업 창 관련 코드(창 만들기, 창 상태, 복귀)는 없앴다.
- **확인하지 못한 것**: 비활성 탭에서 reCAPTCHA v3 토큰과 자동 제출이 활성 창과 똑같이 동작하는지는 실제 제출 없이 확인할 수 없다. 합성 페이지 E2E로 흐름만 확인했다. 비활성 탭에서 자동 제출이 막히면(버튼이 준비되지 않음 등) "직접 확인이 필요해요"로 넘어간다.

## 검증 상태 (2026-11-23, 이슈 #23)

로그인한 상태의 제출 페이지는 직접 볼 수 없어서 공개 자료로 구조를 확인했다. 제품 책임자가 실제 계정으로 수동 확인해야 한다.

| 항목 | 상태 | 근거 |
|---|---|---|
| 언어 번호(node.js 17, Python 3 28, PyPy3 73, C++17 84, Java 11 93) | 확인 | 공개 채점 현황 페이지의 언어 필터 `<option>` 값 |
| 채점 현황 표 구조, 결과 코드, 실시간 갱신 방식 | 확인 | 공개 채점 현황 페이지 HTML과 백준 공개 스크립트(`status.js`, `app.min.js`) |
| `www.acmicpc.net` → `acmicpc.net` 리디렉션, 비로그인 시 `/login?next=/submit/{id}` | 확인 | 공개 페이지 응답 |
| 제출 페이지 에디터가 CodeMirror 5(`.CodeMirror` → `el.CodeMirror`) | 미확인(공개 자료) | 백준허브 `submitfilter.js`와 여러 공개 사용자 스크립트가 같은 방식을 쓴다 |
| 언어 select `#language`와 chosen.js(`#language_chosen`), `chosen:updated`로 표시 갱신 | 미확인(공개 자료) | 공개 자동화 코드가 `#language_chosen`을 다룬다. chosen.js는 컨테이너 id를 `{select id}_chosen`으로 만들므로 select id는 `language`로 본다 |
| 제출 뒤 `/status?from_mine=1&problem_id={id}&user_id={아이디}`로 이동, 머리글 `a.username` | 미확인(공개 자료) | 백준허브 파싱 코드 |
| 채우기·배너·결과 보고 전체 흐름 | 합성 페이지로 확인 | Playwright E2E(`e2e/submit.spec.ts`)가 백준 구조를 본뜬 페이지에서 언어·코드 채우기, 제출 미발생, 한 번만 채우기, 결과 저장을 확인한다 |

## 결과

- PRD의 '제출 후 채점하기' 한 번 클릭 흐름은 '제출하기 → 백준에서 제출 버튼 클릭' 두 단계가 된다.
- 확장은 백준에 어떤 요청도 직접 보내지 않는다. 필요한 권한은 `acmicpc.net`의 콘텐츠 스크립트뿐이다.
