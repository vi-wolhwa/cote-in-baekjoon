# ADR-0005: 모의 시험

- 상태: 승인 (2026-11-24)
- 관련: M4, #99 ~ #102, PRD 6장 M4

## 배경

여러 문제를 시간 제한 안에 푸는 모의 시험을 만든다. 제품 책임자가 정한 것(2026-11-24):

- 시험 중 제출 결과는 **시험이 끝난 뒤** 공개한다.
- 문제 세트는 solved.ac 조건(티어, 알고리즘, 문제 수)으로 고르고, **로그인된 백준 아이디로 이미 푼 문제를 뺀다**(끌 수 있음).
- 시작은 팝업의 '모의 시험' 탭과 백준 문제 메뉴의 '모의시험'(코딩테스트와 제출 사이).
- 화면은 #99의 시안(시험 만들기, 시험 화면, 결과 화면)을 따른다.

## 결정

**문제 고르기: solved.ac 검색 API**
- `GET https://solved.ac/api/v3/search/problem?query=…&sort=random&page=1`
  - 티어 `*s5..g1`, 알고리즘 `(#dp|#greedy)`, 이미 푼 문제 빼기 `!s@아이디`, 200명 이상 푼 문제만 `s#200..`, 한국어 문제 `lang:ko` (응답 형태와 태그 키는 2026-11-24 실제 API로 확인)
  - 결과에서 앞의 N개를 쓴다. 모자라면 사용자에게 조건을 넓히라고 안내한다.
- **포함할 문제**(2026-11-24 제품 책임자 요청): 사용자가 문제 번호를 직접 넣고 뺄 수 있다. 넣은 문제는 난이도·알고리즘·이미 푼 문제 빼기와 관계없이 꼭 들어가고, `GET /api/v3/problem/show?problemId=…`로 제목과 레벨을 읽는다(solved.ac가 모르는 번호면 시작하지 않는다). 나머지(문제 수 − 넣은 문제 수)만 검색에서 넣은 문제를 빼고 채우며, 넣은 문제로 문제 수가 다 차면 검색하지 않는다.
  - 넣은 문제 수는 문제 수를 넘을 수 없다: 다 차면 추가가 꺼지고, 문제 수는 넣은 문제 수보다 줄일 수 없고, 시작할 때 한 번 더 확인한다.
  - 백준 메뉴의 '모의시험'은 그 문제를 넣은 채로 폼을 열지만 뺄 수 있다. 팝업은 빈 목록으로 시작한다. 목록은 `ui:exam-draft`에 저장하지 않는다.
- 권한: `optional_host_permissions`에 `https://solved.ac/*`를 두고, 처음 시험을 만들 때 `permissions.request`로 묻는다. 설치할 때 경고가 늘지 않는다.
- 요청은 사용자가 '시험 시작'을 누를 때만 보낸다. 자동 갱신이나 미리 받아 두기는 하지 않는다.

**백준 아이디**
- 콘텐츠 스크립트가 백준 페이지의 로그인 정보(상단 사용자 링크)를 읽어 `boj:handle`로 저장한다. 사용자가 백준에 들어갈 때마다 갱신한다.
- 아이디를 모르면 '이미 푼 문제 빼기'를 끄고 이유를 보여 준다.

**문제 본문**
- 시험 화면이 열리면 1번 문제부터 읽는다. 백그라운드가 `https://acmicpc.net/problem/{번호}`를 같은 창의 **비활성 탭**으로 연다. 사용자가 문제 페이지를 여는 것과 같은 일반 방문이다.
- 1번을 읽은 뒤 나머지 문제도 저절로 읽는다(2026-11-24 제품 책임자 요청). **한 번에 하나**(탭 하나), 문제 순서대로, 사이에 0.5초 쉰다. 이미 읽은 문제는 건너뛰고, 사용자가 아직 안 읽은 문제를 열면 그 문제를 먼저 읽는다. 시험이 끝나면 멈춘다. 읽는 동안 레일의 번호는 흐리게, 지금 읽는 문제에는 작은 회전 표시가 보인다. 사용자가 시작한 시험의 문제(최대 8개)만 읽으므로 크롤링이 아니다(CLAUDE.md의 예외 문구).
- 그 탭의 문제 페이지 콘텐츠 스크립트가 백그라운드에 "읽으러 연 탭인지" 묻고, 맞으면 풀이 화면 오버레이와 같은 `parseProblem`으로 읽어 보낸다(MathJax가 바꾸는 동안은 잠깐 기다린다). 이 탭에는 메뉴 버튼과 자가 진단 안내를 넣지 않는다.
- 백그라운드는 보낸 탭이 그 문제를 읽으려고 연 탭인지, 문제 번호가 맞는지 확인하고, 페이지 데이터로 보고 모양을 검사한 뒤 시험 기록에 저장하고 탭을 닫는다. 진행 중인 읽기는 `storage.session`의 `cib:capture:{시험 id}:{문제}`에 탭 id와 함께 둔다(서비스 워커는 언제든 멈출 수 있다).
- 한 문제에 읽기는 하나만: 다시 눌러도 탭을 더 열지 않는다. 20초 안에 끝나지 않으면 탭을 닫고 이유와 '다시 시도'를 보인다. 사용자가 탭을 닫거나 문제를 읽지 못하면(페이지 구조 변경) 그 이유를 보인다.
- 읽은 결과는 시험 기록에 저장해 다시 열지 않는다. 읽지 못한 문제는 저절로 다시 시도하지 않고, 문제 영역의 '다시 시도'로만 다시 읽는다. 시험 밖의 문제를 미리 받아 두는 일은 없다.
- 권한: 새 권한이 필요 없다(탭 열기·닫기, 이미 있는 콘텐츠 스크립트). `host_permissions`는 두지 않는다.
- 처음에는 확장 페이지에서 문제 페이지를 `fetch`했지만, 백준은 탐색이 아닌 요청에 본문이 빈 200 응답을 준다(쿠키·헤더와 무관, 같은 출처 `fetch`도 같음). 의도된 수집 방지이므로 우회하지 않고 위 방식으로 바꿨다(2026-11-24).

**답안 저장과 끝난 뒤 한꺼번에 제출** (2026-11-24 제품 책임자 요청으로 바꿈)
- 시험 중 '제출하기'는 백준에 제출하지 않는다. 지금 코드와 언어를 그 문제의 답안(`answers[문제] = { code, language, savedAt }`)으로 저장하고 레일에 ✓를 단다. 다시 누르면 답안이 바뀐다. 에디터 코드가 저장한 답안과 다르면 하단에 "저장한 답안과 달라요"를 보인다(저장한 답안만 제출되므로).
- 시험이 끝나면(시험 종료 확인, 시간 끝, 끝난 뒤 시험 화면을 열었을 때) 결과 화면으로 가서 저장한 답안을 **하나씩 차례로** 백준에 제출한다. 동시에 내지 않는 이유: 제출마다 공식 제출 창, reCAPTCHA 토큰, 채점 현황 페이지가 따로 필요하고, 창을 여러 개 띄우면 보안 확인에 걸리거나 결과를 놓칠 수 있다.
- 각 답안은 지금 흐름(공식 제출 창, 자동 제출, ADR-0002)으로 내고, 채점 현황이 그 제출을 알려 주거나(`judge:{문제}` 갱신) 실패할 때까지 기다린 뒤, 그 창이 닫히면 다음을 낸다.
- 진행 상태는 시험 기록의 `submitQueue[문제] = { state: pending | submitting | manual | submitted | failed, reason? }`에 둔다. 낼 차례가 된 답안은 먼저 'submitting'으로 표시한 뒤 낸다. 새로고침이나 서비스 워커 재시작 뒤 'submitting'으로 남은 답안은, 그 뒤 결과가 왔으면 제출됨, 제출 창이 아직 열려 있으면 계속 기다림, 아니면 '제출 실패'(확인 불가)로 두고 저절로 다시 내지 않는다. 같은 답안을 두 번 내지 않는다.
- 자동 제출이 멈추면(보안 확인, 언어 목록에 없음, 방화벽 문자열) 20초 뒤 '직접 제출이 필요해요'와 '제출 창 보기'를 보이고, 사용자가 처리해 결과가 오거나 창이 닫히면 다음으로 넘어간다. 실패한 답안은 '다시 제출'로 다시 낸다.
- 시험 중에는 아무것도 제출하지 않으므로 채점 현황 페이지를 덮는 방식(`hideResult`)은 없앴다. 끝난 뒤 결과는 공개다.

**시간**
- 남은 시간은 시작 시각과 제한 시간으로 계산한다(타이머와 같은 방식, `src/ide/timer.ts`). 0이 되면 자동으로 끝난다. 끝난 뒤에는 답안을 바꿀 수 없다(제출하기를 막는다).

**저장**

| 키 | 내용 | 백업 |
| --- | --- | --- |
| `exam:{시험 id}` | 조건, 문제 목록(번호·제목·solved.ac 레벨·읽어 온 본문), 시작·끝 시각, 제한 시간, 다시 볼 문제, 문제별 답안(코드, 언어, 저장 시각), 제출 진행 상태, 문제별 백준 제출(언어, 시각, 그 제출의 채점 결과) | 포함 |
| `ui:exam-draft` | 마지막으로 고른 조건 | 포함 |
| `boj:handle` | 로그인된 백준 아이디 | 제외(다시 읽으면 됨) |
| 코드 | 연습과 같은 `code:{문제}:{언어}` | 포함 |

**화면**
- 시험 만들기 폼은 하나의 컴포넌트로 만들어 팝업 '모의 시험' 탭과 `exam.html#setup`(백준 메뉴 '모의시험'이 여는 새 탭, 그 문제를 '포함할 문제'에 넣은 채)에서 함께 쓴다.
- 시험 화면 `exam.html#{시험 id}`: 풀이 화면 구성(문제·에디터·실행 결과)에 왼쪽 문제 레일(번호 버튼, 답안 저장 초록 체크, 다시 볼 문제 노란 깃발, 읽기 전 흐림)과 오른쪽 사이드바의 남은 시간을 더한다(2026-11-24 제품 책임자 요청으로 가로 번호 줄에서 바꿈). 상단에 '시험 종료'.
- 결과 화면 `exam.html#{시험 id}/result`: 제출 진행("제출 중 2/4"), 맞은 문제 수, 걸린 시간, 문제별 상태(제출 대기 / 제출 중 / 직접 제출이 필요해요 / 채점 결과 / 제출 실패 + 다시 제출)·언어·답안 저장 시각.

## 결과

- solved.ac가 응답하지 않거나 권한을 거절하면 시험을 만들 수 없다. 팝업에서 이유와 다시 시도를 보여 준다.
- 시험을 시작하면 그 시험의 문제(최대 8개)를 백준 문제 페이지로 하나씩 비활성 탭에 열었다 닫는다. 탭 표시줄에 잠깐씩 탭이 보인다.
- 끝난 뒤 저장한 답안은 실제 백준 제출이다. 하나씩 내므로 답안이 많으면 몇 분 걸릴 수 있고, 그동안 결과 화면을 열어 두어야 한다(닫으면 다시 열 때 이어서 낸다).

## 구현하며 정한 것 (2026-11-24)

문제 본문을 읽는 방식은 위 '문제 본문'처럼 바꿨다(fetch → 비활성 탭). 그 밖에 ADR에 없던 세부를 아래처럼 정했다.

- **문제 고르기**: 검색 결과에서 제출할 수 없는 문제(`isSolvable: false`)는 뺀다. 넣은 문제는 `problem/show`로 읽어 넣고, 검색 결과에 같은 문제가 있으면 겹치지 않게 뺀다. 문제 순서는 넣은 문제를 포함해 모두 실제 시험처럼 쉬운 문제부터(solved.ac 레벨 오름차순)다. 시험 기록에는 넣은 문제 번호를 `included`로 둔다(전에 만든 기록의 `include` 하나도 읽는다).
- **결과 묶기**: 답안을 백준에 낸 시각을 기록한다. `judge:{문제}`가 그 시각 뒤, 그 시각(또는 시험 끝)에서 30분 안에 바뀌었을 때만 시험 결과로 본다. 시험 화면이나 결과 화면이 열려 있는 동안 받은 결과는 시험 기록에 복사해 두므로, 나중에 같은 문제를 연습해 `judge:{문제}`가 바뀌어도 시험 결과는 그대로다.
- **결과 숨기기**: 시험 중에는 제출하지 않으므로 숨길 결과가 없다. 그래도 시험이 진행 중이면 팝업 홈의 '최근 푼 문제'와 통계에 그 문제들의 결과를 넣지 않는다(연습 결과로 답을 엿보지 않게). 같은 문제를 다른 탭의 연습 화면에서 열면 그 화면의 채점 결과 탭에는 보인다(막지 않음).
- **다시 풀기**: 결과 화면의 '다시 풀기'는 백준 문제 페이지를 `#cib-ide`로 열고, 콘텐츠 스크립트가 이 표시를 보면 연습 풀이 화면을 바로 연다.
- **E2E 테스트**: 자동화는 Chrome의 권한 확인 창을 누를 수 없다(`--apps-gallery-install-auto-confirm-for-tests`도 `permissions.request`에는 듣지 않음을 확인). 그래서 E2E는 빌드 결과의 복사본에서 solved.ac를 필수 권한으로 옮겨 실행한다(`e2e/fixtures.ts`의 `grantSolvedAc`). 제품 빌드는 바꾸지 않고, 권한을 묻고 거절하는 흐름은 단위 테스트로 확인한다.
