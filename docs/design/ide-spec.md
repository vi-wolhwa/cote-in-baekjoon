# 풀이 화면 디자인 명세

PRD 8장 결정에 따라 풀이 화면을 기업 코딩테스트 풀이 화면(프로그래머스 연습 화면)과 같게 만든다.

- 이 문서의 값은 2026-11-23에 1440×900 화면에서 로그인 없이 실제 화면의 계산된 스타일을 측정한 것이다.
- 그쪽의 이미지·스타일시트·스크립트 파일은 쓰지 않는다. 이 값으로 직접 구현한다.
- 이름·로고·아이콘은 쓰지 않는다.
- 측정하지 못한 항목은 **[미확인]** 으로 표시했다.

## 1. 배치

| 영역 | 크기 | 비고 |
|---|---|---|
| 상단 바 | 높이 47px, 배경 `#0C151C`, 안쪽 여백 6px 16px | 왼쪽 경로 표시(14px, 현재 항목 흰색 700), 오른쪽 링크(16px, `#B2C0CC`) 도움말·문제 신고·백업과 복원. 맨 오른쪽 '돌아가기'는 강조한다(§10) |
| 제목 줄 | 높이 56px, 배경 `#263747`, 안쪽 여백 0 16px | 문제 제목(16px, 흰색). 오른쪽에 키맵 선택(sublime/vim/emacs)과 언어 선택 |
| 본문 | 좌우 분할 40 : 60 | 구분선 24px, 최소 0, `ew-resize` |
| 오른쪽 | 상하 분할 에디터 60 : 결과 40 | 구분선 14px, 최소 60px, `ns-resize` |
| 하단 바 | 높이 57px, 안쪽 여백 8px 16px, 위 테두리 1px `#172334` | 버튼 높이 40px |

## 3. 글꼴

- **UI**: `Inter, NotoSansKR, "Helvetica Neue", Helvetica, Arial, "맑은 고딕", sans-serif`
- **문제 본문**: 16px, 줄 높이 28.8px, 자간 −0.1px. h4 16px 굵게, h5 15px.
- **고정폭**: `Hack, Menlo, Monaco, Consolas, monospace`
  - 에디터 16px, 줄 높이 22.4px
  - 결과 14px, 줄 높이 1.5
  - 코드 블록 14px

## 4. 에디터 동작

- 줄 번호, 자동 줄바꿈, 탭 크기 4, 들여쓰기 4칸(공백), 현재 줄 강조, 괄호 짝 표시, 괄호 자동 닫기
- 키맵: 기본 `sublime`, `vim`, `emacs` 중 선택. 선택은 저장해서 유지한다.
  - sublime: 선택 영역에서 Tab은 들여쓰기, Shift-Tab은 내어쓰기
- 파일 탭 이름: `solution.<확장자>`
- 언어 선택: 목록에서 고른다. 이 제품은 백준 언어 ID에 맞춘다 (PRD 6장 순서).

## 5. 버튼과 대화상자

**하단 바 순서**
- 왼쪽: 질문하기(백준 질문 게시판 링크, 테스트 케이스 추가하기와 같은 어두운 버튼), 테스트 케이스 추가하기
- 오른쪽: 초기화, 코드 실행, 제출하기(주 버튼)
- 질문하기·다른 사람의 풀이는 백준의 질문 게시판·맞힌 사람 링크로 대신할지 M1에서 정한다.

**초기화 대화상자**
- 제목: 초기화 안내
- 본문: "지금까지 작성한 모든 코드가 삭제되고 문제를 처음 시작했을 때의 상태로 돌아갑니다. 초기화 하시겠습니까?"
- 버튼: 취소, 확인
- 확인 후 결과 창: "코드를 초기화하였습니다."

**테스트 케이스 추가**
- 제목: 테스트 케이스 추가
- 표준 입출력 문제는 Input / Output 열을 쓴다.
- 배치는 **[미확인]** 이다.

**실행 중**: 중지 버튼이 나타나고, 중지하면 "실행 중단"을 표시한다.

## 6. 실행 결과 출력 형식

- 구분 기호는 "〉"(U+3009, 불투명도 32%)다.
- 라벨은 오른쪽 정렬된 10rem 폭 열에 `#44576C`로 쓴다.
- 빈 상태: "실행 결과가 여기에 표시됩니다."

```
테스트 1
     입력값 〉 1 2
     기댓값 〉 3
   실행 결과 〉 테스트를 통과하였습니다.
        출력 〉 (표준 출력이 있을 때만)
```

**통과·실패 문구**
- 통과는 파란색이다.
- 실패는 빨간색으로 "실행한 결괏값 X이(가) 기댓값 Y와(과) 다릅니다."를 표시한다.

**요약**
- "테스트 결과 (~˘▾˘)~" 제목 뒤에 "N개 중 M개 성공"을 쓴다. 모두 통과하면 파란색, 아니면 빨간색이다.
- 모두 통과하면 다음 안내를 덧붙인다: "샘플 테스트 케이스를 통과했다는 의미로, 작성한 코드가 문제의 정답은 아닐 수 있습니다."

**오류**
- 런타임 에러: 빨간 제목 "런타임 에러", 그 아래 표준 에러 내용
- 상태 문구: 실패, 시간 초과, 메모리 초과, 런타임 에러, 출력 크기 초과
- 시간 초과 설명: "실행 시간이 N초를 초과하여 실행이 중단되었습니다. 실행 시간이 더 짧은 다른 방법을 찾아보세요."

**채점 결과** (제출 후, 백준 결과를 이 형식으로 보여 준다)
- "채점을 시작합니다." 뒤에 결과 줄이 나온다. 예: `정확성 테스트 〉 맞았습니다!! (12ms, 11.2MB)`

## 7. 문제 영역

- 안쪽 여백 16px, 영역 안에서 세로로 스크롤한다. 맨 위에 '문제 설명' 라벨이 있다.
- 섹션 사이에 `hr`(1px `#172334`, 위아래 24px)을 둔다.
- 표: 셀 `#202B3D`, 테두리 1px `#172334`, 안쪽 여백 4px 12px
- 코드 블록: 배경 `#202B3D`, 안쪽 여백 20px 24px, 반경 4px
- 백준 문제는 섹션 순서대로 표시한다: 문제, 입력, 출력, 제한, 예제 입력·출력, 힌트

## 10. 오른쪽 사이드바와 설정 대화상자

2026-11-24, 1024×768에서 측정했다.

**사이드바**
- `<aside>` 폭 64px. 상단 바 바로 아래(위에서 47px)부터 창 아래 끝까지 이어진다.
- 다크: 배경 `#263747`, 왼쪽 테두리 1px `#172334`. 라이트: 배경 `#FFFFFF`, 왼쪽 테두리 1px `#D7E2EB`.
- 첫 버튼은 설정(톱니)이다. 32×32 아이콘 버튼, 반경 4px, 투명 배경, 가로 가운데, 사이드바 위에서 16px.
  - 아이콘 20px, 색 `#98A8B9`
  - 호버 배경: 다크 `#172334`, 라이트 `#E9ECF3`
- 사이드바 위에서 76px에 폭 31px, 1px 구분선(다크 `#172334`, 라이트 `#D7E2EB`)이 있다.

**역할 나누기** (2026-11-24 제품 책임자 결정)
- 사이드바는 지금 문제를 푸는 데 쓰는 도구만 둔다: 설정, 구분선, 타이머.
- 확장 전체 메뉴는 상단 바에 둔다: 도움말 → 문제 신고 → 백업과 복원 → (오버레이일 때) 강조된 돌아가기. 같은 기능을 두 곳에 두지 않는다.
  - 문제 신고: 버그 신고 이슈 양식을 새 탭으로 연다. 버전·브라우저·문제 번호·언어를 미리 채운다. 코드는 넣지 않는다.
  - 오픈소스 라이선스는 상단 바에서 빼고 도움말 페이지 맨 아래, 버전 옆에 링크로 둔다.

**타이머** (이 제품에서 더한 버튼, 참고 화면에는 없다)
- 구분선 아래 16px. 설정과 같은 32×32 아이콘 버튼(직접 그린 스톱워치 선 아이콘), `title`·`aria-label` "타이머".
- 시작한 뒤에는 아이콘 아래에 시간을 작게 보인다(11px, 600, `tabular-nums`, 예: `12:34`, `1:02:03`). 버튼은 그만큼 커진다.
  - 도는 중: 강조색(다크 `#5AA2FF`, 라이트 `#0053F4`). 11px 글자가 4.5:1을 넘도록 다크에서는 `#0078FF`보다 밝게 했다.
  - 일시정지: 흐린 색(다크 `#98A8B9`, 라이트 `#5F7F90`)
  - 시간 종료: 빨강(다크 `#FF7B7B`, 라이트 `#D32F2F`)으로 천천히 깜빡인다. 동작 줄이기 설정이면 깜빡이지 않는다.
- 누르면 사이드바 왼쪽 8px에 팝오버가 열린다. 모달이 아니라 나머지 화면은 그대로 쓸 수 있다. Esc나 바깥 클릭으로 닫고, 닫아도 시간은 계속 간다.
  - 폭 280px, 안쪽 여백 16px, 반경 8px, 테두리 1px, 그림자. 풀이 화면 테마를 따른다.
  - 다크: 배경 `#263747`, 안쪽 면 `#202B3D`, 글자 `#FFFFFF`/보조 `#B2C0CC`, 테두리 `#172334`
  - 라이트: 배경 `#FFFFFF`, 안쪽 면 `#F7F7FB`, 글자 `#263747`/보조 `#5F7F90`, 테두리 `#D7E2EB`
  - 맨 위 두 칸 선택: 스톱워치 | 타이머(기본 스톱워치). 시간이 가고 있거나 멈춰 있으면 초기화해야 바꿀 수 있다(실수로 기록을 잃지 않게).
  - 가운데 큰 시간: 36px, 600, `tabular-nums`. 한 시간 미만 `mm:ss`, 이상 `h:mm:ss`. 화면 읽기 프로그램이 매초 읽지 않도록 `aria-live="off"`.
  - 스톱워치: 시작/일시정지(주 버튼 `#0078FF`), 초기화(보조 버튼).
  - 타이머: 시작 전에는 시간 자리가 "0시간 30분" 입력 칸이 된다(위아래 화살표로 1씩). 아래에 빠른 선택 30분·60분·90분·120분. 기본 30분, 1분~9시간 59분. 범위를 벗어나면 시작이 꺼지고 안내가 나온다.
  - 0이 되면 시간이 빨갛게 바뀌고 "시간 종료 · 30분이 지났어요."가 나온다. 화면 읽기 프로그램에는 "시간 종료"를 한 번만 알린다. 소리는 내지 않는다. 주 버튼은 "다시 시작"이 된다.
- 상태는 문제마다 `storage.local`의 `timer:{문제 번호}`에 `{ mode, running, startedAt?, elapsedMs, durationMs }`로 둔다. 보이는 시간은 언제나 시각 차이로 계산하므로 풀이 화면을 닫았다 열거나 새로고침해도 이어진다. 잠깐 쓰는 값이라 백업에는 넣지 않는다. 예시 문제(번호 0)는 저장하지 않는다.
