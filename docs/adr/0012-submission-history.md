# ADR-0012: 문제별 제출 기록과 백준 기록 불러오기

- 상태: 채택
- 날짜: 2026-11-25
- 관련: #61(M7 제출 기록), ADR-0002(제출과 채점 결과), ADR-0001(문제 페이지 위 오버레이), ide-spec 7.3

## 배경

제품 책임자 제안(#61): 왼쪽 문제 영역에 제출 기록 탭을 두어 지난 제출의 결과와 코드를 보고, 지난 코드를 다시 불러올 수 있게 한다. 지금은 문제마다 마지막 채점 결과 하나(`judge:{문제}`)만 남고, 제출한 코드는 남지 않는다.

#61의 실현 가능성 분석은 다음과 같다.

1. 확장으로 낸 제출의 코드·결과 기록: 제출할 때 로컬에 저장하면 되고 백준 요청이 없다.
2. 백준에서 직접 낸 과거 제출: 백준 채점 현황을 읽어야 한다. 백준 이용 규칙이 웹 스크래핑을 금지하므로, 사용자가 누를 때 한 페이지만 읽는다.
3. 상위 기록과 비교·분포: 이번 범위에서 뺀다(후속 작업).

## 결정

### 1. 확장 제출 기록 (저장 모델)

- **키**: `storage.local`의 `history:{문제 번호}`. 값은 그 문제의 제출 목록이고 최신순이다.
- **항목**:

  | 필드 | 내용 |
  |---|---|
  | `problemId` | 문제 번호 |
  | `language` | 확장의 언어 id(`python3`, `cpp17` …) |
  | `code` | 백준에 보낸 프로그램 그대로 |
  | `fnCode` | solution 함수 모드(ADR-0006)로 냈을 때 사용자가 쓴 함수. `code`는 여기에 입출력 코드를 붙인 것이다 |
  | `submittedAt` | 제출하기를 누른 시각(밀리초). 문제 안에서 항목을 가리키는 키다 |
  | `result` | 채점 결과: `solutionId`(백준 제출 번호), `status`, `resultCode`, `resultText`, `memoryKb`, `timeMs`. 받기 전에는 없다 |

- **기록 시점**: 백그라운드가 제출 요청(`cib:submit-request`)을 받아 제출 탭을 연 뒤에 항목을 넣는다. 연습 풀이 화면과 모의 시험의 제출이 모두 이 길을 지나므로 한 곳에서 기록한다. 제출 탭을 열지 못하면 기록하지 않는다. 기록에 실패해도 제출은 계속한다.
- **결과 연결**: 채점 현황이 결과를 보고하면(ADR-0002 결정 4) `judge:{문제}`를 쓴 뒤 같은 결과를 기록에도 붙인다.
  - 붙일 항목은 감시(`cib:watch:{문제}`)를 시작한 제출이다. 감시는 제출할 때마다 새로 시작하므로, 감시 시작 시각 1분 전 이후에 기록된 가장 최근 항목을 고른다. 1분 여유는 '결과 다시 확인'이 풀이 화면의 시계로 감시를 다시 시작하기 때문이다.
  - 채점 중 → 최종 결과처럼 같은 제출의 결과는 갱신하고, 이미 붙은 것보다 작은 제출 번호의 보고와 같은 결과의 반복은 무시한다.
- **한도**: 문제마다 최근 **50개**. 넘으면 오래된 것부터 지운다. 코드는 한 항목에 최대 512 KB(기존 제출 한도 `MAX_CODE_LENGTH`)다. `unlimitedStorage` 권한이 이미 있어 저장소 한도에는 걸리지 않지만, 한 키의 값이 너무 커지면 읽고 쓰는 비용이 커진다. 50개면 보통 코드(수 KB)로 수백 KB 안이고, 지난 제출을 다시 보는 데 충분하다.
- **쓰기 순서**: 기록은 한 키를 읽고 고쳐 쓰므로 백그라운드 안에서 한 번에 하나씩 처리한다(모듈 안의 대기열). 서비스 워커가 멈춰도 상태는 저장소에만 있다.
- **검증**: 저장소와 백업 파일에서 읽은 값은 항목마다 검사하고 틀린 항목은 버린다.
- **백업**: `history:{문제}`를 백업·복원에 넣는다. 합치기 복원은 양쪽 목록을 제출 시각으로 합친다(같은 시각이면 지금 것을 남기고, 최신 50개). 요약에 "제출 기록 N개"를 보인다.

### 2. 백준 기록 불러오기 (요청 규칙)

> 2026-11-25 개정으로 바뀌었다(아래 '개정'). 백준이 스크립트 요청을 막아 이 방식은 더 쓰지 않는다.

- '제출 기록' 탭의 **백준 기록 불러오기**를 **누를 때만** 요청한다. 탭을 열 때, 풀이 화면을 열 때, 주기적으로는 보내지 않는다.
- **한 번 누르면 한 요청**: 그 문제의 사용자 자신의 채점 현황 첫 페이지 `GET /status?problem_id={문제}&user_id={아이디}`(최근 20개)만 읽는다. 다음 페이지나 다른 문제는 읽지 않는다.
- **간격**: 요청이 진행 중이거나 앞 요청 뒤 3초가 지나지 않았으면 보내지 않고 "몇 초 뒤에 다시 눌러 주세요"를 보인다.
- **누가 보내나**: 풀이 화면은 확장 페이지 iframe이라 `acmicpc.net` 호스트 권한 없이는 직접 요청할 수 없다. 그래서 문제 페이지의 콘텐츠 스크립트가 같은 출처 요청(`fetch`, `credentials: 'same-origin'`)으로 보낸다. 새 권한이 필요 없다.
  - 풀이 화면 → 콘텐츠 스크립트: `postMessage`(`cib:boj-history-request`, 임의 nonce). 콘텐츠 스크립트는 메시지가 자기가 만든 iframe에서 왔는지 확인한다.
  - 문제 번호는 메시지가 아니라 콘텐츠 스크립트가 읽은 문제에서 쓴다.
  - 응답은 확장 출처로만 보내고, 풀이 화면은 백준 출처와 nonce를 확인한다.
- **아이디**: 문제 페이지 머리글의 로그인 아이디(`a.username`, ADR-0005의 `readHandle`)를 쓴다. 없으면 **요청하지 않고** "백준에 로그인하지 않은 상태예요…"를 보인다. 받은 페이지에 로그인 아이디가 없어도(그사이 로그아웃) 같은 안내를 보인다.
- **신뢰하지 않는 입력**: 받은 HTML은 `DOMParser`로 실행·로드 없는 문서로만 만든다. `#status-table`의 행 가운데 그 사용자·그 문제의 행만 골라 결과(ADR-0002의 `parseStatusRow`), 메모리, 시간, 언어(7번째 칸, " / 수정" 링크 앞 이름), 코드 길이(8번째 칸), 제출 시각, 제출 번호만 꺼낸다. 글자 길이와 개수(20행)를 자르고, 풀이 화면이 다시 검사한 뒤 글자로만 보인다. 표가 없으면 "모양이 달라 읽지 못했어요"를 보인다.
- **저장하지 않는다**: 읽은 행은 화면에만 보이고 저장하거나 확장 기록과 합치지 않는다.
- **소스 보기**: 행의 '코드 보기 ↗'는 백준 `/source/{제출 번호}`를 새 탭으로 여는 보통 링크다. 확장은 소스 페이지를 요청하거나 읽지 않는다.

### 3. 화면

- 연습 풀이 화면의 문제 영역에 '문제 설명 | 제출 기록' 탭을 둔다. 자세한 값은 ide-spec 7.3.
- 결과 배지 색은 실행 결과와 같다(맞았습니다 `--pass`, 그 밖의 최종 결과 `--fail`).
- 편집기로 불러오기는 제출의 언어와 모드로 바꾼 뒤 코드를 넣는다. 바뀔 코드가 비었거나 시작 코드나 같은 코드가 아니면 먼저 묻는다.
- 코드 복사는 iframe에서 클립보드 쓰기가 허용되도록 오버레이 iframe의 `allow`에 `clipboard-write`를 더한다. 막히면 코드를 선택해 두고 Ctrl+C를 안내한다.
- 모의 시험 화면에는 탭을 두지 않는다(시험 중 지난 코드를 보는 것은 시험 취지에 맞지 않는다). 시험에서 낸 제출도 기록은 되어 연습 화면에서 보인다.

## 결과

- 확장으로 낸 제출은 코드와 결과가 문제별로 남고, 다시 불러올 수 있다. 백준 요청은 늘지 않는다.
- 백준 기록은 누를 때 한 요청뿐이다. CLAUDE.md의 '사용자 동작 때만 백준에 요청' 규칙 안에 있어 따로 예외를 두지 않는다. 개인정보 처리방침(`docs/privacy.md`)에 요청과 저장 항목을 적었다.
- 백준 채점 현황의 칸 순서(언어 7번째, 코드 길이 8번째)가 바뀌면 그 두 값이 틀린다. 결과·메모리·시간·제출 번호는 기존 선택자(클래스)로 읽으므로 영향이 작다. 합성 픽스처(`tests/fixtures/status-history.html`)로 테스트한다.
- 확인하지 못한 것: 실제 로그인 상태의 채점 현황에서 언어 칸의 정확한 모양(" / 수정" 링크)과 소스 공개 설정에 따른 차이는 공개 자료와 합성 페이지로만 확인했다.

## 후속

- #61 3번 '상위 기록과 비교'(사용자가 누를 때 '맞은 사람' 첫 페이지만 읽기)는 백준 운영사 문의 결과(`docs/ops/boj-inquiry.md`)에 따라 따로 진행한다.
- 기록 지우기(한 항목, 문제 전체)는 사용 피드백을 보고 정한다.

## 개정 (2026-11-25): 채점 현황 표, 자동 불러오기, 다른 사람 기록

제품 책임자 요청: 백준 기록 불러오기가 "모양이 달라 읽지 못했어요"로 실패한다. 풀이 화면 제출과 백준 기록을 합쳐 자동으로 불러오고, 백준 채점 현황처럼 표로 보이며, 아래에 이 문제의 모든 사람 채점 현황을 자동으로, 페이지를 넘기며 보이게 한다. 왼쪽 영역에 최소 너비를 둔다.

### 실패 원인

2026-11에 백준이 사이트 전체에서 스크립트 요청(`fetch`, XHR, iframe)에 빈 본문(200, 길이 0)을 돌려주기 시작했다. 문제·채점 현황·사용자 페이지 모두 같고, 브라우저 탭으로 열 때만 내용이 온다. 그래서 결정 2의 같은 출처 `fetch`는 표 없는 빈 문서를 받아 '모양이 다름'으로 끝났다. 같은 시기 채점 현황에 '채점 서버' 열이 생겨 언어·코드 길이 칸의 위치도 한 칸씩 밀렸다.

### 결정 (결정 2를 바꾼다)

- **읽는 방법**: 백그라운드가 채점 현황 페이지를 문제 탭 바로 옆의 **비활성 탭**으로 열고, 그 탭의 채점 현황 콘텐츠 스크립트가 페이지를 읽어 넘기면 탭을 닫는다(모의 시험 문제 읽기, ADR-0005와 같은 방식). 스크립트 접근을 막은 백준의 의도를 비켜 가는 방식이라는 점을 제품 책임자에게 알리고 승인을 받았다(2026-11-25). 사람이 직접 여는 것과 같은 페이지를, 사람보다 느린 속도로 연다.
  - 요청은 확장 페이지(풀이 화면)만 보낼 수 있고, 백그라운드는 한 번에 한 페이지만, 앞 페이지가 끝난 뒤 1초 이상 지나 연다. 20초 안에 읽지 못하면 탭을 닫고 "응답하지 않아요"를 보인다.
  - 답은 그 요청으로 연 탭이 같은 채점 현황 주소에서 보낸 것만 받는다. 상태는 서비스 워커 메모리에만 둔다(한 요청이 몇 초뿐이고 풀이 화면이 메시지 채널을 열어 두고 기다린다). 워커가 멈추면 풀이 화면이 "연결하지 못했어요"를 보이고 '새로 고침'으로 다시 시도한다.
  - 새 권한은 없다(`tabs.create`·`tabs.remove`는 권한이 필요 없고, 콘텐츠 스크립트는 이미 `/status`에서 돈다).
- **언제 읽나**: '제출 기록' 탭을 열 때 '내 제출'(`/status?problem_id=…&user_id={아이디}`)과 '채점 현황'(`/status?problem_id=…`) 첫 페이지를 차례로 자동으로 읽는다. 다음 페이지(`top=`)는 사용자가 '다음 페이지'로 불러온 줄을 넘어갈 때만 읽는다. 풀이 화면을 열 때나 주기적으로는 읽지 않는다. 같은 목록은 1분 안에 다시 읽지 않는다(탭을 오가도 탭이 열리지 않는다). '새로 고침'은 첫 페이지부터 다시 읽는다.
- **아이디**: 문제 페이지를 열 때 머리글에서 기억한 로그인 아이디(`boj:handle`)를 쓴다. 모르면 '내 제출'은 확장 기록만 보이고 백준은 '채점 현황'만 읽는다. 사용자별 채점 현황은 공개 목록이라 로그인 여부와 상관없이 읽힌다.
- **파싱**: 언어와 코드 길이는 머리글 이름('언어', '코드 길이')으로 칸을 찾는다. '언어' 머리글이 없으면 '모양이 다름'이다. 요청한 문제(와 아이디)의 행만, 한 페이지 20행까지 꺼내고 이전·다음 페이지 링크의 `top`을 읽는다. 받는 쪽(백그라운드, 풀이 화면)이 모두 다시 검사하고 글자로만 보인다.
- **합치기**: '내 제출'은 확장 기록과 백준 행을 한 목록으로 합쳐 최신순으로 보인다. 같은 제출 번호는 한 줄(값은 백준, 코드는 확장 기록)이다. 백준의 다음 페이지를 아직 읽지 않았으면 마지막으로 읽은 백준 행보다 오래된 확장 기록은 그 페이지를 읽을 때 보여, 페이지를 넘겨도 이미 본 줄 위에 줄이 끼어들지 않는다. 확장 기록은 그대로 문제마다 50개, 백준 행은 저장하지 않는다(풀이 화면 메모리에만 1분).
- **화면**: 두 표를 백준 채점 현황과 같은 열로 보이고, 스크롤바가 생기지 않도록 표 높이에 맞는 줄 수씩 페이지로 나눈다(ide-spec 7.3). 문제 영역은 320px, 오른쪽은 360px 아래로 줄지 않는다(연습·시험 화면).
- **소스·사용자**: 제출 번호와 아이디는 백준의 소스·사용자 페이지를 새 탭으로 여는 보통 링크다. 확장은 소스 페이지를 읽지 않는다.

### 결과

- 백준에서 직접 낸 제출도 탭을 열면 바로 보이고, 이 문제의 다른 사람 제출도 백준과 같은 순서로 넘겨 볼 수 있다.
- 탭을 열 때 백준 탭이 두 번(내 제출, 채점 현황) 잠깐 나타났다 사라진다. 페이지를 넘길 때도 한 번씩 그렇다.
- 백준이 탭으로 여는 페이지까지 막으면 이 기능은 '모양이 다름' 또는 '응답 없음'으로 실패한다. 그때는 '백준에서 보기 ↗' 링크만 남기는 쪽으로 되돌린다.
- CLAUDE.md의 '사용자 동작 때만 백준 요청' 예외 목록에 이 탭을 더했다. 개인정보 처리방침에 요청과 항목을 고쳐 적었다.

## 개정 2 (2026-11-25): 세 보기, 언어 필터, 숏코딩, 다른 사람 코드 보기

제품 책임자 피드백: 두 표를 한 화면에 두니 높이가 애매하다. 내 제출·채점 현황·숏코딩을 탭으로 나누고, 채점 현황과 숏코딩에 언어 필터를 둔다. 다른 사람이 공개한 코드는 눌러서 내 제출처럼 볼 수 있어야 하고, 공개 여부가 바로 보여야 한다. 제출 번호는 필요 없고, 결과 문구는 길이를 맞춰 새로 디자인하며, 코드는 구문 색으로 보인다.

### 결정

- **보기**: '내 제출 | 채점 현황 | 숏코딩' 탭. 각 보기는 처음 열 때 첫 페이지를 읽는다(제출 기록 탭을 열면 '내 제출'만 읽어 개정 1보다 요청이 줄었다). 한 번 연 보기는 다른 보기로 가도 페이지 위치를 지킨다.
- **언어 필터**: 채점 현황은 `language_id`, 숏코딩은 `/short/status/{문제}/{언어}/{쪽}`. 목록은 백준의 묶음(C++ 1001, Java 1002, Python 1003, C 1004, Rust 1005)과 자주 쓰는 언어로 줄였다(`LANGUAGE_FILTERS`).
- **숏코딩**: `/short/status/{문제}[/{언어}]/{쪽}` 한 쪽(20줄)을 읽는다. 열은 머리글 이름(등수, 제출 번호, 아이디, 메모리, 시간, 언어, 코드 길이, 제출한 시간)으로 찾는다. 다음 쪽은 그 쪽 번호 링크가 있고 줄이 20개일 때만 있다.
- **코드 공개 여부**: 백준은 보는 사람이 읽을 수 있는 코드의 언어 칸을 `/source/{제출 번호}`로 링크한다(로그인 상태에서 확인, 2026-11-25). 그 링크가 있으면 '열 수 있음'으로 표시하고 줄을 누를 수 있게 한다. 없으면 자물쇠. 내 제출은 언제나 열린다.
- **코드 읽기**: 줄을 누를 때 `/source/{번호}`를 같은 방식(비활성 탭, 한 번에 하나)으로 열어 코드 편집기의 `textarea[name="source"]`에서 코드만 읽는다(최대 512 KB). 로그인하지 않았으면 백준이 `/login?next=/source/…`로 보내므로, 그 로그인 페이지에서 "로그인해야 해요"로 답한다. 읽은 코드는 화면에만 있고 저장하지 않는다. 누를 때만 읽으므로 '사용자 동작 때만' 규칙 안이다.
- **편집기로 불러오기**: 백준 언어 이름을 확장 언어로 바꿀 수 있으면(`BOJ_LANGUAGES`의 이름) 다른 사람 코드도 불러올 수 있다. 바꿀 수 없으면 버튼이 없다.
- **표시**: 제출 번호 열을 없애고, 결과는 아이콘이 붙은 짧은 칩(정답, 오답, 시간 초과 …)으로 길이를 맞췄다. 누를 수 있는 줄은 굵은 글씨 대신 마지막 칸의 코드 아이콘·마우스 올림 바탕·손 모양 커서로, 공개하지 않은 코드는 자물쇠로 구분한다. 코드는 편집기와 같은 테마의 읽기 전용 CodeMirror로 보인다. 자세한 값은 ide-spec 7.3.

### 결과

- 개정 1의 "탭을 열면 두 페이지" 대신 보기마다 한 페이지씩 읽는다. 코드 보기는 누를 때 한 페이지다.
- 새 콘텐츠 스크립트(`boj-capture.content.ts`)가 숏코딩·소스·로그인 페이지에서 돈다. 읽으라고 연 탭이 아니면 아무것도 하지 않는다. 새 권한은 없다.
- 소스 페이지 구조(`textarea[name="source"]`)와 언어 링크는 로그인한 브라우저에서 확인했고, 테스트는 합성 픽스처(`tests/fixtures/short-page.html`, `source-page.html`)로 한다.

## 개정 3 (2026-11-25): 맞힌 사람, 큰 화면 채우기, 확장 쪽 기록 없애기, 코드 임시 저장

제품 책임자 피드백: 채점 현황보다 실행 시간순인 맞힌 사람이 더 필요하다. 큰 화면(QHD)에서는 한 쪽에 20줄보다 많이 들어간다. 제출 코드는 백준에서 읽으면 되니 확장이 따로 저장할 필요가 없고, 문제를 새로 열 때 예전 코드가 남아 있을 필요도 없다. 다만 실수로 창을 닫았을 때는 되살려야 한다. 언어 필터에는 지금 편집기 언어가 '모든 언어' 바로 아래에 와야 한다.

### 결정 (결정 1과 개정 2의 일부를 바꾼다)

- **보기**: '내 제출 | 맞힌 사람 | 숏코딩'. 채점 현황 보기를 없앴다. 맞힌 사람은 `/problem/status/{문제}[/{언어}]/{쪽}`이고 숏코딩과 같은 모양이라(시도 열 하나가 더 있다) 같은 파서·페이지 규칙을 쓴다. 열은 실행 시간이 앞에 온다.
- **화면 채우기**: 표 높이에 들어가는 줄 수가 읽은 줄보다 많고 다음 쪽이 있으면, 다음 쪽을 하나씩 이어서 읽는다(읽기에 실패하면 멈춘다). 그 밖의 다음 쪽은 넘길 때만 읽는다.
- **언어 필터**: '모든 언어', '현재 언어 (백준 이름)', 그다음 언어들을 알파벳순(대소문자 무시, 숫자는 크기순)으로. '현재 언어'는 편집기 언어를 따라가고 백준 언어 번호로 바꿔 쓴다(JavaScript → node.js 17, Python 3 → 28, …).
- **확장 제출 기록 없앰** (결정 1을 거둔다): `history:{문제}`에 코드와 결과를 쌓지 않는다. 내 제출은 백준 채점 현황만 보이고, 코드는 누를 때 소스 페이지에서 읽는다(내 코드는 늘 열린다). 편집기로 불러오기는 백준이 보관한 전체 프로그램을 표준 입출력 모드로 넣는다(solution 함수만 따로 되살리지 않는다). 제출하면 목록 캐시를 지워 다음에 열 때 새 제출이 보인다. 백업은 `history:` 키를 만들지 않고, 예전 백업에 있으면 조용히 건너뛴다.
- **코드 임시 저장**: 편집기 코드는 지금처럼 문제·언어별 키(`code:{문제}:{언어 묶음}`)에 저장하되 값에 저장 시각을 붙인다(`{ code, savedAt }`). 연습 풀이 화면은 마지막 저장 뒤 **3시간** 안이면 되살리고, 그보다 오래되면 시작 코드로 연다. 모의 시험은 시험 동안 그대로 읽는다(시각 제한 없음). 3시간은 창을 실수로 닫고 돌아오는 경우는 넉넉히 덮고, 다음 날 다시 열 때는 새로 시작하게 하는 값이다.
- **정리**: 설치·업데이트·브라우저 시작 때 `history:*`와 마지막 저장 뒤 2일이 지난 `code:*`(예전 버전이 시각 없이 저장한 것 포함)를 지운다. 2일은 모의 시험 길이보다 넉넉하다.

### 결과

- 저장소에 문제마다 쌓이던 제출 코드와 오래된 언어별 코드가 사라진다. 업데이트할 때 예전 코드도 지워진다(제품 책임자 결정).
- 백준에 로그인하지 않았거나 아이디를 모르면 내 제출이 비고, 그 이유를 보인다.
- 큰 화면에서는 탭을 열 때 백준 페이지를 두 번 이상 읽을 수 있다(한 번에 하나, 1초 간격).
